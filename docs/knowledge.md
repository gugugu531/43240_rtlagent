## 模式与准入

`rtl_generate` 节点支持 `skill_mode`、`rag_mode`，均为 `off / shadow / on`。自适应工作流的同名参数位于顶层 `params`。

- `off` 不检索、不装配。
- `shadow` 检索并记录准入，但不更改生成消息，也不请求知识装配的 tokenizer。记录的是“准入后待装配”，不宣称已通过 token 预算。
- `on` 只有通过准入和预算的完整知识段才进入请求。

工具编译输出没有版本时，RAG 可额外探测版本用于检索准入和日志。自适应修复的基础消息只保留编译输出自身携带的版本；额外探测所得版本及探测标识不进入基础消息，因此 `shadow` 不会借由诊断元数据改变求解提示。原始检查记录和检索使用的版本证据完整保留。

旧配置兼容：未设置模式时，非空 `skill_ids` 表示 Skill on；`rag: true` 表示 RAG on。显式模式与旧 `rag: true` 冲突时报配置错误。自适应 Skill 默认 on，保留原主机映射，经同一个准入层过滤。

自动准入只放行 catalog 中 `review_status=frozen_default_fixed` 的 Skill：时序 v2 可自动准入；v3 候选仅供固定注入实验，位宽、组合逻辑、FSM 仍处于 fixed A/B 拒绝状态。自动选择被拒绝时记录原因并继续无知识生成；显式选择拒绝／未知／冲突 Skill 仍在构图阶段报错，模型请求之前停止。`adaptive_verify` 的 `sequential_skill` 在构图阶段用 catalog/资产做同一自动准入校验，配置为未经批准的 v3 候选会在任何模型请求前报错，不再静默失效。

自适应路由只产生 Skill 候选，不直接授权发送：`route.json` 记录 `skill_candidates`（`skill_ids` 仅为进程内只读别名，不落盘），实际发送看知识装配的 `skill_selected`/`sent` 与预算。若路由分析显示无时钟（`analysis.clocks` 为空）且任务为 sequential/protocol 或命中无时钟 latch 门禁，候选会移除时序方法，避免向无时钟状态题注入要求时钟状态更新的方法。checker 不消费 Skill。自动路由入口是主线 `choose_route`，离线旧路由器不被视为第二个运行时权威。路由收益尚未验收。

## 统一检索接口

`retrieval` 配置：

| 字段 | 默认值 |
| --- | --- |
| `strategy` | `exact`；可选 `bm25 / dense / hybrid` |
| `retrieve_k` | 5，上限 32 |
| `inject_k` | 1，本版固定上限 |
| `fallback` | `empty`；可显式改为 `exact` |
| `release_id` | `framework-v1-en.1` |
| `release_sha256 / policy_sha256` | 未显式设置时使用随包 `runtime-lock.json`；显式值必须与锁文件一致 |
| `embedding_url` | 空；服务根 URL，客户端追加 `/v1/embeddings` |
| `embedding_transport` | `http`；可选 `ssh` |
| `embedding_timeout_s` | 2 秒，最大 10 秒 |
| `embedding_ssh_host / embedding_ssh_port` | 空 / 22；仅 SSH 使用 |

HTTP 不使用环境代理，不跟随跳转。SSH 要求已有可信主机密钥，服务 URL 必须是远端 loopback HTTP；只运行固定 curl 请求，查询通过标准输入传输。模型别名、1024 维度、有限数值和非零向量均验证。别名校验不能替代服务端权重哈希审计。

发布包包含 32 张英文卡及冻结文档向量，不含开发查询、标签、参考 RTL 或判定结果。BM25 使用冻结分词与参数；dense 为精确点积；hybrid 为 exact/BM25/dense 的 RRF（常数 60）。F24 是额外受限 exact 通道，没有伪造向量，trace 用 `lane: restricted_exact` 区分。完整系统排名不能直接冒充原 32 卡离线指标。

embedding 只接收限长、路径脱敏后的首个有效工具诊断及工具元数据，不接收完整题面或 RTL。知识准备最多使用剩余请求窗口的 10% 且不超过 5 秒；embedding 超时进一步限制在该窗口的一半，给生成保留时间。超时、断连、响应 JSON 结构不合法、模型／向量不兼容按配置降级，记录有效后端及延迟；HTTP 200 也必须通过结构校验。服务失败使用 `retrieval_unavailable`，不算正确空返回；还应检查 `embedding_error` 和 `effective_strategy`。

## 保守准入边界

检索先检查候选 ID／哈希、执行 ID、检查器哈希、状态、诊断完整性和版本。只采用工具顺序中的首个非级联 error，次生诊断不能授权注入。

32 卡原政策中的 `model_not_needed`、`correct_empty_by_default`、缺功能夹具等直接拒绝。自然语言“缺失事实”不能靠词面猜测：尚无机械证据时记录 `missing_fact_not_mechanically_established`，不开放注入。明确反馈片段以及候选／原始反馈哈希绑定的 correct_empty 检查点也能拒绝；自适应反馈不是旧检查点原始格式时，不伪造哈希命中。

本版正向注入路径是 F24：lint、xvlog 2026.1、首诊断 VRFC 10-4982 且 `syntax error near ','`、当前代码存在错误复制项拼接形态；先排除注释与字符串。无候选形态、未知版本、次生错误、已提供相同方法均不注入。正则是受限形态守卫，不是完整 Verilog 语法证明，仍须重新检查和功能验证。

原 `knowledge/cards.json` 六卡快照保留为历史资产，不是本版检索入口。不要把六卡宽匹配称为 F24 准入。K=1 天然禁止卡间共同注入；扩大 K 必须实现并验收冲突政策，不能仅修改上限。

## 发布与记录

`python -m agent.knowledge.publish <实验仓库>` 从声明源文件生成 `knowledge/runtime-v1.json` 与摘要；参数是包含 `dev/rag` 冻结源文件（corpus、index、准入策略、F24 投影）的开发仓库路径。发布验证 corpus/index 配对和 F24 投影哈希；运行加载再检查文件摘要、唯一 ID、文档投影哈希和向量。Skill 仍使用 catalog 的版本／正文哈希／状态校验。源文件变更需重新发布和验收，禁止直接手改向量。

英文发布采用 schema 2，并生成 `runtime-lock.json`。每条准入规则、检查点规则和文档向量元数据都绑定实际英文卡的 `card_version` 与规范 JSON 的 `card_sha256`。旧策略版本仅保留在 `source_card_version` 作来源记录，不能参与当前卡版本匹配。F24 的卡哈希与确定性谓词 ID 单独绑定；发布锁同时固定准入策略、索引和六卡快照的摘要。历史六卡版本更新为 `1.0.1-burr.en.1`，其原 `source` 仍表示上游来源，不冒充译文哈希。

`repair_rag_shadow.yaml` 显式固定发布／策略摘要；其它开启 RAG 的配置至少使用同一锁文件，显式错误 pin 在模型调用前拒绝。重新发布后应同步显式 pin 并运行测试，不能只改外层文件摘要。翻译改变了生成提示的语言，因此旧效果结果不自动成为本版收益证据。

每次装配记录 `skill_selected / skill_rejected`、`retrieval.retrieved / admitted / rejected`、完整段预算结果和 `sent`，并保存原消息／实际消息哈希与耗时。`model_result` 绑定 call ID。可选资源或 tokenizer 失败保留原消息继续求解；配置错误由预检处理，硬性总任务超时不吞掉。

`framework-outcome.json` 的汇总 schema 为 2，汇总完整新稿交付、候选选择、solution 哈希、工具结果和阶段成本。`latest_complete_candidate_id` 只统计有明确 `complete_new_draft: true` 交付证据的候选，按候选创建顺序取最后一份；交付通过候选 ID 绑定，只有未记录候选 ID 的旧式自适应事件才通过唯一的模型调用 ID 关联。创建候选、保存答案和默认 `extraction_status` 均不能证明完整性。

`selected_candidate_complete` 为 true／false／null，表示明确完整、明确不完整或缺少证据。baseline 保持主办方提取行为，未执行完整性验证时为 null；此时 `selected_latest_complete` 也为 null。`selected_latest_complete` 不等于“本次修复成功”：没有新稿时 latest complete 仍可能是旧稿，须同时检查 `deliveries`；完整交付也不代表 RTL 通过编译或功能检查。外部评分与评分候选默认为 null，不猜测尚未运行的主办方评分。

### 共同起点 失败与需求登记

每个问题登记公开规格来源与版本、设计家族、自然失败候选哈希、检查执行身份、诊断或公开反例、已给提示、既有方法或卡片覆盖、分类理由和待验证假设。区分如下情况：

| 失败类别 | 优先工作线 | 不应采取的替代动作 |
| --- | --- | --- |
| 缺少检查步骤，且有明确可检查目标 | Skill 局部方法 | 因为属于 FSM 或算术就自动注入 |
| 做了检查但关系推导错误 | 共享机械检查与方法可靠性 | 只加长 Skill 或把 thinking 当真值 |
| 缺少可迁移语言、工具或设计事实 | RAG 候选卡 | 把整题解法或隐藏要求写入卡片 |
| 事实已有但未召回 | 查询与检索审计 | 再创建同义卡或先放宽准入 |
| 召回了但适用性或增量无法确认 | 准入谓词与证据绑定 | 把未知空返回算作 correct_empty |
| 未交付、检查拒绝、修复未落实或引入新错误 | 交付与修复链 | 把所有问题归因于知识库不足 |
| 题面歧义、检查器或环境问题 | 隔离、修正规格或工具链 | 利用参考答案反推模型不可见要求 |

同一失败可以有多个原因，但应指定本轮主要干预对象。共享修复链保持 thinking 开启；当前采用单阶段实验基线，不恢复未经证明有益的两阶段，也不转交截断 thinking。若修改交付链或检查器，先单独验证，再冻结为两组共同底座。

### Skill 主线 先证明需求 再证明局部方法

主线：真实失败分类 → 方法需求与独立检查 → 最小正文候选 → 固定注入配对 → 需求准入 → 自动路由 → 最后联合使用。

1. **重建需求样本。** 保留 v7 为已知容易样本和冗余注入回归，不继续把其「method_gap_hypothesis」当作已证实缺口。优先从自然失败发现值得检查的表达式或状态边界，再用公开规格构造独立开发样本。每种方法同时覆盖缺方法、反馈已给方法、主题相关但不适用。探索样本与事先冻结的确认样本分开，完整记录筛选与失败，不能只复测胜出的题。
2. **先准备机械产物，再改正文。** 位映射、分支选择关系、短时序关系须转成能抓住错误实现的检查。测试至少包含正确实现、目标错误、相邻边界错误，并验证确实执行了比较。两组使用相同检查、反馈、接口约束与工具额度；是否提供额外工具须另做实验，不计入正文收益。
3. **按最小方法单元修复和扩充。** 每个单元只说明触发证据、最小对象、检查产物、停止条件；通用接口保护和完整交付要求留在基础提示中。扩充的是经验证的方法分支，不是把所有方法累计注入。

| 顺序与类别 | 下一版方法边界 | 检查产物与停止条件 |
| --- | --- | --- |
| 先位宽 | 一个表达式的操作含义、边界位映射、宽度与符号；先功能后位宽 | 边界或单个置位输入、符号边界；目标与相邻关系通过后停止扩展分析 |
| 再组合逻辑 | 将漏赋值与完整赋值但函数错误分开 | 出错分支及相邻分支的选择关系；默认赋值不能替代功能修复 |
| 再 FSM 子类型 | 按当前证据只选输出状态集合、计数边界、完成脉冲、异常恢复之一 | 最后两个采样沿、完成沿和下一沿，或局部状态输出集合；不顺带重论证整个协议 |

时序 v2 保持现有参照，不随本轮改写。协议 FSM 独立处理位序、采样沿和异常恢复的公开可检查案例，不阻塞其他方法，也不通过猜测评测预期解决未交付。

4. **固定框架比较正文。** 先无 Skill 对局部候选，保持模型身份、thinking、采样参数、总预算、公开反馈一致；在同一主机内比较，不能跨服务配置归因墙钟差异。有跨独立样本可重复的收益信号后，再加入简短通用提醒对照，区分具体方法与一般提醒。相同代码只支持效率比较；同种子重复不是新增独立样本。
5. **最后做需求准入与路由。** 候选路由判断相关方法，需求准入判断本次是否缺这个方法、目标是否可检查、反馈是否已经提供。经常返回无 Skill 是正常结果。先验证固定注入方法，再验证选择是否准确、实际发送是否发生以及端到端成本；不能因路由器已实现就宣称路由有效。

阶段交付：失败—方法清单、三类方法的版本化正文与检查包、按独立题族的配对报告、需求准入正反例。推进条件是预先声明的交付与成功率不退步边界、可重复的成功或全链成本改善，以及无明显长尾恶化；阈值和重复安排写入运行前清单。未达标保留为候选或拒绝，不因排期恢复默认注入。

### RAG 主线 从候选知识到可验证运行卡片

主线：失败与覆盖差距 → 上游资料候选池 → 卡片验证包与增量谓词 → 版本化发布 → 固定检索器比较旧库与扩展库 → 分批扩库 → 再优化检索器。

1. **先盘点现有 32 卡及独立 F24 通道。** 按「确实不需要、谓词未实现、证据路径缺失、版本不支持、运行失败、可准入待效果验证」分别列账。先解决有真实需求的现有卡，已明确重复的 genvar 诊断保留为拒绝用例，不删去诊断中的修复信息人为制造增量。新版 generate 识别器已不固定模块及信号名称，但仍仅支持受限结构，不能当完整语法分析器。
2. **建立广覆盖但不上线的候选池。** 2026-10-26 用户进一步明确：100 条不是上限，允许建立 200 条以上的知识候选池，不设置人为数量封顶，也不以数量作为有效性或上线指标。按实际失败类型和独立家族覆盖排序，区分工具版本事实、语言规则和设计原则；重复条目合并，不将变量改名、格式变体、待调研主题算成新增知识。候选池内容不自动进入运行索引或模型提示。
3. **逐卡交付验证材料。** 每卡包含一个窄事实；当前证据已知内容；额外提供的事实；允许触发的工具、版本、源代码结构或公开功能反馈；重复、不适用、定位不足、版本未知等拒绝条件；最小复现、正确与错误实现、正负例及变体；来源、使用与分发条件、版本、哈希、数据家族。状态区分候选、机械验证、实验可用、默认可用；机械验证不代表已证明模型收益。
4. **实现共享版本化准入。** 绑定当前候选、诊断文件和位置、主次诊断、执行与检查器身份。测试变量重命名、格式、参数、无关模块、错误作用域、过期反馈与知识已提供。结构适用、未明确提供同一事实、实测有益分别记录；前两者不是对模型内部知识状态的证明。开发与运行共用实现，通过显式策略版本选择，不再维护两套分叉规则。
5. **先完成发布工程，再小批上线实验。** 运行卡数量由发布清单声明，取代 `runtime.py` 固定 32 的假设；同时检查发布器、配置 `retrieve_k` 限制、测试夹具和锁文件。保留数量、唯一 ID、卡片／文档／规则集合、版本及哈希、索引投影、向量维度的完整性验证。向量语料与 F24 等独立 exact 通道分别声明数量与绑定，禁止重复计数或伪造向量。覆盖缺卡、额外卡、重复 ID、旧索引、错版本和损坏锁文件测试；保留旧包可回滚。只在新发布版本实施，不修改正在运行的冻结包。
6. **首批选择约 10–15 条最有证据的新增候选。** 数量用于控制工作量，不是必须凑齐的门槛；证据不足可少于该数。优先真实诊断有定位、官方依据明确、当前反馈缺少关键事实的窄卡。先验证每张卡触发与拒绝，再冻结卡片、准入、预算，对比旧库和扩展库，观察新增独立失败覆盖、误注入、冗余注入、交付、全尝试成功、成本和原通过样本退步。
7. **分离扩库、准入与检索变化。** 若需要先完善准入，两套库均用同一更新后的准入实现，再比较增加卡片的影响；旧准入与新准入的收益另报。固定检索算法、参数、模型与旧文档向量，新增卡按同一编码契约建立向量。扩库会自然改变排名和 BM25 语料统计，应记录；不能同时换 embedding 或调排名参数。首批成立后再扩展，最后固定卡片与准入比较 exact、BM25、dense、hybrid。

功能性 RAG 单列为前置工程：输入必须是公开规格导出的期望、实际观测、时钟／复位与采样语义、对应代码位置，以及候选和检查执行绑定。编译通过但行为错误不能靠编译错误码或 FSM 主题触发；反馈不足时保留未知。先让正确与错误实现证明公开检查有区分力，再讨论功能卡注入。不得把隐藏测试、参考答案或推断出的隐藏要求写进卡片或模型反馈。

空返回至少分为：有证据确认不适用或重复的正确空返回、无法判断的未知空返回、运行失败导致的空返回。策略标记 `model_not_needed` 不自动证明本次知识重复；命中率、未知率、失败率分别报告，分母应包括已标注的知识需求机会，防止「全部拒绝」被当作成功。

### 来源与评测隔离

采用两层资料结构：广覆盖资料层用于发现与核实，运行卡片层只收经验证的窄事实。

- 官方语言及工具文档、Answer Records 提供规则与版本依据。采用具体结论前核对章节、工具版本和适用上下文，记录可复查的来源快照或内容哈希。
- [Ross 仓库](https://github.com/Xilinx/ross-ai-assistant)提供 Agent Skills、文档与示例；其[本地知识库](https://github.com/Xilinx/ross-ai-assistant/blob/main/docs/local-kb/README.md)描述的是覆盖 AMD 工具资料的检索服务，不是我们的修复准入策略或生成模型。初期仅用于离线整理和溯源，不接入当前在线实验，也不因为参考它就引入向量数据库。
- [RTLLM](https://github.com/hkust-zhiyao/RTLLM)提供设计描述、测试及参考 RTL；只能在预先指定的开发分区中用来发现模式和构造检查。同题或同源变体不能同时当独立泛化证据。
- [TuRTLe](https://github.com/HPAI-BSC/TuRTLe)是整合多个基准的评测框架，包含 RTLLM、VerilogEval、VGen、RTL-Repo 与 NotSoTiny 等来源。它不是与这些来源互不重叠的新题库；筛选知识时追溯原始设计与来源版本，分别审计许可、开发分区和题族重叠，不能把包装后的同题算成独立覆盖。
- [RTL-BenchMT](https://github.com/hkust-zhiyao/RTL-BenchMT)保留原始与修订内容，可辅助审计题面歧义；修订版本仍须验证，不自动取代真值，也不混用题面版本比较成绩。

上述链接是来源入口，不是已冻结的引入版本。实际引入前固定提交、文件、日期、内容哈希，并分别审计代码、文档快照、模型、示例的许可与再分发条件；仓库许可证不自动覆盖所有上游资料。

balanced60 一旦用于选方法、选卡或调准入，即为需求发现与开发回归集；v7 自建样本及其反馈变体也属于开发资料。新的留出集在扩充前按原始设计、来源和变体家族登记隔离，不靠改题号或变量名制造独立性。隐藏判定器只用于最终评分，不提供建库依据或修复反馈。参考实现通过现有测试不等于测试充分，必须验证测试能捕获目标错误。

#### 共享链路与验证分层

模型实验开始前必须同时满足以下条件：实际注入文本包含所需的合法正确示例；已有事实扫描覆盖完整题面与公开反馈；源代码、公开反例、检查器、期望表及评分候选身份绑定；卡片、准入、清单和报告使用同一版本与哈希。正确实现必须通过，目标错误与相邻错误必须被同一检查器检出。若其中一项不成立，卡片保持阻塞。

验证层级分别记录来源审查、机械验证和模型配对。机械验证又区分普通编译／仿真、指定前端版本、交叉模拟器、综合网表／资源报告、静态 CDC 与实现后时序。CDC、亚稳态安全、器件映射和物理时序不能用普通 RTL 仿真代替。缺少对应工具、版本、来源或证据适配器时记 `blocked`；资产或服务异常记 `failure`，不能记 correct-empty。

准入负例优先在本地自动覆盖：完整题面或反馈已经给出同一事实返回 `not_needed`；经审阅不适用返回 `not_needed`；定位、版本或证据不足返回 `unknown`；资产或服务异常返回 `failure`。只有正向缺口任务进入全量首轮模型配对；少量跨证据路径的端到端负例用于抽查，不为逐字相同的请求重复消耗生成调用。

#### 首轮与追加规则

每张 ready 卡首轮只运行一个有区分力的正向配对：同一失败代码、同一公开反馈、模型、thinking、预算和检查器，无卡与单卡两臂只有实际注入文本不同。若 136 张全部 ready，理论上是 136 对／272 次调用，但这不是当前可运行数或完成承诺。33376 采用家族轮转，单卡失败隔离后继续下一卡；共享身份、评分或证据绑定错误才暂停受影响家族，若错误属于共享底座则暂停全队列。

首轮后的追加选择在运行前固定：功能退步、语法错误、未交付或显著长尾先归因并修订／隔离；成功救援换独立上下文确认；成本明显下降追加独立上下文并检查尾部；两臂都轻松成功且成本接近则本轮停止。确认结果单独汇报，不能混回首轮平均值；历史任务也单列为回归。两条独立有效开发家族均无价值时，停止该卡本轮模型开销。
