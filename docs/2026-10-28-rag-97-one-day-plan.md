## 1. 当天目标与冻结范围

交付一个可执行的实验版本：扩展知识资产能加载，embedding 能根据题面检索，真实准入器能决定使用或拒绝，首个生成请求能注入一张适用卡，并完成小规模无 RAG／RAG 配对及审计。

| 资产集合 | 数量 | 本轮处理 |
| --- | ---: | --- |
| 完整适配机械证据候选卡 | 97 | 唯一新增资产研究范围；统一身份、影子索引与分层验证 |
| 部分合同证据卡 | 27 | 全部暂时冻结，不重构、不补工具证据、不加入本轮索引和队列 |
| 能力阻塞卡 | 12 | 继续冻结，不安装专用工具或寻找新器件来解除阻塞 |
| 现有运行库 | 32 | 保留为基线，处理与 97 张之间的身份及事实重复关系 |

“其他卡全部冻结”在本计划中指候选池中 27+12=39 张。冻结保留历史文件，禁止本轮检索、准入、注入、模型配对、机械重跑和发布；以后解冻需有新的明确决定。

32+97=129 是合并前数量上限，并非必须发布的卡数。去重、冲突或证据版本不匹配可使实际纳入数量减少。机械通过不直接授予注入资格。97 张中的综合／器件卡也不因本轮范围收缩而自动适用于纯题面生成。

- [ ] 复用冻结的 Qwen3-Embedding-0.6B 配置，绑定模型文件、维度、归一化、文本投影和索引哈希。
- [ ] 为首次生成增加独立的题面查询投影：任务要求、接口、位宽／符号、时钟／复位、边界、延迟、工具／器件条件。
- [ ] 每项抽取结果记录题面原文片段；题面没有的信息保持未知。
- [ ] 保留诊断检索入口，新增题面检索入口；首次生成不伪造编译失败、源码诊断位置或检查执行 ID。
- [ ] 实现 dense 和 BM25 离线基线；先检索 top-5 候选，再执行准入，初版实际注入不超过 1 张。

建议准备 40–60 条无模型检索查询，覆盖可适用、主题相近但不适用、已有事实、合同不足及工具版本冲突。查询需分为调试集和冻结检查集；分别标注“相关卡”与“允许注入卡”，报告 Recall@5 和准入错误，不把相似度当成适用性证明。

验收：索引不含冻结卡，检索结果可复现；题面路径不依赖编译日志；超时和资产异常能走到预期降级。

### P2：首次生成前路由（7–12 小时）

- [ ] 在真实第一次生成的装配入口接入“题面抽取 → 检索 → 准入 → 去重／预算 → 注入”。
- [ ] 为首次生成证据绑定题面哈希、接口哈希、阶段、查询哈希和卡片版本；生成后的反馈使用另外的证据类型。
- [ ] 从 97 张中选择最多 6–8 张低风险卡开展首轮注入研究；不为凑数量放宽准入。
- [ ] 题面方法已给、工具条件不明、卡片互相冲突或合同不足时返回空。
- [ ] 为卡片声明 `pre_generation`、`post_diagnostic` 或 `post_functional_feedback` 适用阶段。F24 等诊断依赖卡继续留在诊断路径。
- [ ] 记录 retrieved、admitted、actually_sent 三层结果，以及拒绝理由、检索与 embedding 延迟。

初筛可考察 conditional-X merge、indexed-select constant width、NBA RHS sampling、sticky event memory、context-before-operation 和 const-not-parameter。它们只获得优先审查资格；实际名单取决于题面是否能确认适用、卡片是否提供新增实现知识以及当前版本的历史处置。只有修复场景证据的卡不能直接算作首次生成已验证卡。

区分“题面规定目标”与“题面已经提供实现方法”：规定饱和行为并不自动意味着已经给出防溢出的中间宽度方法。反之，完整实现公式已经提供时通常应拒绝重复卡片。

验收：通过真实工作流发出的第一次生成请求已包含获准卡；shadow 请求与基线逐字相同；路由使用的输入没有包含后续检查结果。

### P3：小规模端到端对照（12–19 小时）

- [ ] 冻结 20–30 道公开开发任务，优先复用合同已审计、检查器可信的不同任务家族；标记历史曝光关系。
- [ ] 任务包含实际需要卡片、事实已经给出、主题相关但不适用和合同不足的场景，禁止只挑必然命中的样例。
- [ ] 对每题运行无 RAG 和题面 dense RAG 两臂，生成模型、thinking、seed、预算与检查器相同，保留真实请求和回复。
- [ ] 本轮计划 40–60 次生成调用；保持 thinking 开启，无自动重试。
- [ ] 使用同一冻结题面的 off/shadow 装配消息做本地相等性检查，不为相同消息额外重复生成。
- [ ] 每个任务先用正确实现、目标错误和相邻错误验证检查器，并核对题面足以决定评分要求。
- [ ] 不调用模型填补缺失题面合同；遇到模数、相位、延迟或表示方式不确定，先修合同或将该题隔离。

主指标：首稿完整交付率、全尝试成功率、新错误和未交付、全部尝试的输入＋输出 token、embedding 与生成总延迟、总调用次数。分别报告获准注入任务和拒绝注入任务，保留全部任务总指标。

若合同审计或共享评分发现错误，暂停受影响队列并保留已完成记录；共享错误解除前不继续消耗模型调用。普通单题失败记录后继续，不自动重跑。

## 4. 资源、预算与截止策略

- 本地负责代码、资产整理和无模型测试；33376 执行 embedding 服务核对、必要的 Vivado 预检和模型调用。
- 模型调用串行执行。重型 Vivado 作业与模型服务错峰，避免资源竞争使延迟不可比。
- 40–60 次调用按每次 2–5 分钟估算，纯生成约 1.3–5 小时；输出上限耗尽或网络异常可能延长时间。先用前 4 个完整配对更新预计耗时。
- 第 19 小时起进入收尾，停止开启预计无法在剩余时间内完成并审计的新配对；以完整配对为单位安排预算。

- 若不能完成全部 97 张 schema 映射，则交付完成子集与逐卡暂缓理由，不能将未验证条目默认为可注入。
