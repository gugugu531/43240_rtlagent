## 1. 六小时的交付目标

交付一个可加载、可回退的统一知识发布候选：原 32 张与新增 97 张使用统一目录、版本和证据清单；每张卡显式声明能被检索、能在哪个阶段使用、允许 shadow 还是受限注入。实际自动注入只覆盖完成真实准入验证的少数方法。

“写入知识库”和“自动发送给模型”分别验收。所有 97 张可登记为正式候选／机械资产；出现退步的版本标记暂停注入。六小时内争取把少量有效方法接入真实工作流并完成确认，不承诺给 97 张全部实现可靠题面准入。

本轮台账中 49 张完成新配对，18 张保留旧配对证据，4 张被筛选器拒绝，26 张仅机械验证。其中新配对注入臂 45 张通过，加上 18 张保留证据，共 63 张有本台账可追溯的通过记录；这是当前版本／所列历史版本证据的计数，**不等于 63 张已完成独立上下文、通用准入或首次生成验收**。

## 3. 题面路由还缺什么

当前真实首次生成链路已经具备“题面／接口 → 检索 → 准入 → 预算 → 第一次请求”的工程接口，但只有六类 pre_generation 方法，实际搜索池也是这六张。129 张向量、97 张反馈观察和夜间 49 个固定配对都不能扩大这个计数。

六小时内以现有六类为基础：

1. 将权威题面、接口、基础提示、待修源码、真实诊断分开传入准入器。题面路由没有待修源码时，不伪造结构证据。
2. 修正 `or previous`、看到任意 `>>>`、看到任意 `<=`、看到任意 parameter／part-select 就拒绝的规则。区分“题面说明所需行为”和“已经给出实现方法”，按具体表达式或赋值验证已知事实。
3. 分别记录“没有证明需要”与“已经证明不需要”。缺条件为 unknown，完整重复／不适用为 not_needed，资产或服务异常为 failure。
4. 现有六类各准备八条冻结开发场景：两个正例、两个独立改写、一个已有方法、一个相邻不适用、一个合同不足、一个冲突／否定。共 48 条，运行真实准入器和装配器；不能由预期标签生成 actual。
5. 重点真实首次生成验证 indexed-select、conditional-X、NBA、sticky 四类。加法进位和算术右移先保持 shadow，原因是已有成本长尾。新修复卡如 size-cast 的反馈配对证据不直接授予首次生成权限。
6. off/shadow、预算不足、知识重复和服务失败下，实际生成请求与同条件基线一致；on 时记录 retrieved、admitted、actually_sent 和最终消息哈希。新增卡每次最多一张，知识预算维持 1024 token。

题面路由目标是一个有明确支持范围的可用版本。对其余卡逐条申明“无题面谓词／需工具证据／暂停注入”，使覆盖缺口可见。

## 4. embedding 还缺什么

模型保留 Qwen3-Embedding-0.6B Q8_0；使用已经复现一致的 f114f91 portable CPU 程序和运行库，固定 last pooling、1024 维、L2 归一化及查询指令版本。

工作重点如下：

- **绑定最新资产**：为变化的文档投影重编码；投影未变的向量按文本哈希复用，重新生成发布／索引锁并验证文档集合一致。统一目录可能仍为 129 张，语义合并后数量以清单为准。
- **区分两种评测**：全目录检索测相关性；阶段过滤后的真实运行路径测准入和发送。禁止把 129 张离线召回成绩当成六张运行池的模型效果，或反过来。
- **补负例覆盖**：保留 97 条开发相关性正查询，新增上述 48 条优先方法场景及公开标签。相关卡与允许注入卡分开标注；不为无谓词的其余卡伪造注入标签。未完成的 194 条全范围负例／已知事实槽位继续明确列为缺口。
- **核查服务和查询长度**：检查模型／维度／非有限值／超时／断连，记录实际 embedding 延迟。保持预先声明的超时和失败回空策略；不以放宽超时掩盖查询过长。
- **审查 compact 查询**：此前 compact 更快但漏掉 partial-products 的 top-5。本轮验证结构化压缩保留位宽、符号、方向、相位和工具条件；无足够证据时保留原投影并记录长查询失败，不默认替换。
- **比较真正不同的生成请求**：同题 BM25/dense 最终完整 payload 一致时复用一次生成，单列复用记录。仅在检索导致不同准入／发送内容时比较下游效果。

六小时内不安排模型微调、更换 embedding、学习型重排或向量数据库建设。现有证据支持先补发布身份、查询覆盖和准入。

## 6. 新调用预算及优先序

建议新额度 **最多 32 次真实生成**，每机最多 16 次，thinking 开启、每臂 max_tokens=16384、单次超时 800 秒、无自动重试。最多输出预算约 524,288 token，输入成本另计；不是要求跑满。

33376 最多八对，优先序如下：

1. size-cast、division、mixed-sign、weighted-product，各一个与历史不同的公开上下文：四对／八次。
2. serial-latch、triangle、grid、empty-star 修订，各一个经过共享检查验证的回归：四对／八次。

第二组只有修订、合同和三变体预检通过才进入模型。无法形成合格修订时保持暂停注入，不为了凑八对启动。gshare 先补共享交错时序检查；本次可不消耗新的模型调用。

33589 主要预算：四个首次生成场景，每题 off／BM25／dense，最多十二次。完整 payload 相同时复用，复用不计新调用、不当作独立观测。另留最多四次给两个事先冻结、确实产生不同最终请求的 BM25/dense 场景；不存在差异则不使用这部分预算。

上一夜平均每次尝试含检查约 106 秒，32 次分两机的生成阶段约 28 分钟／机，但新上下文和未交付长尾可能明显更慢。容量仍按单次 800 秒及工具检查上限调度，不能据平均速度保证全量完成。每次启动完整配对前计算：剩余时间必须覆盖两次调用、检查上限与回传审计余量。工作截止为 T+5 小时，T+6 小时前交付；不够时优先缩减追加配对。

- 最新向量索引与部署一致性记录；全目录相关性和阶段池准入分别报告；异常服务不会阻断普通生成。
- 真实对照的交付率、全尝试成功率、含失败成本、新错误、长尾及请求复用均有审计。
- 最终状态分成“候选／shadow／受限 on／暂停注入”。没有独立证据支持的卡继续保留资产，不消耗在线上下文。

最优先的可交付成果是**统一入库和真实准入修复**。若时间不足，先减少额外生成与检索器差异对照；不删发布身份、实际请求检查或最终审计。全部 97 张通用题面路由及独立泛化验收留待后续。
