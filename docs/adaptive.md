# 自适应工作流与检查

本页描述已实现的 `adaptive_verify`，默认入口保持 `single_generate`。本地机制验证与真实小样本分别记录；实际覆盖和效果须按各自冻结版本核验，不能由受控回复或本地工具通过推断真实模型收益。

## 工作流与配置

`analyze → generate并保存首稿 → build_checker → review_checker → check → decide → repair → recheck → select → finish`。
短分析每题一次，失败直接保守生成；完整首稿立即原子保存。检查器先构造并复核一次，仅正式拒绝进入
`revise_checker → rereview_checker → check`，最多一次修订和重新复核，无返回边。
第二次拒绝、未知、无效或请求不可用均继续结构检查。检查路线依据公开分析与宿主接口/表达能力限制，
在独立模型、局部性质、结构检查中选择。
短分析请求提供带编号的公开原文目录，模型只选择`requirement_ids`，宿主还原原文并严格绑定；
未知/重复编号、混合编号和引用字段均拒绝。历史逐字引用输入仍可严格重放，但新请求不要求模型重新抄写原文。
小模型的8寄存器限制按命名状态变量计数，例如6位数据寄存器加3位计数器是2个变量，不是9个。
检查器构造可返回`status/checker`外层对象或同路线的完整裸检查器对象；两种形式均执行完整预检，
并记录`response_form`。半个外层对象、未知字段及不合法状态仍拒绝；预检通过仍须独立复核，不能直接取得修复权限。
编译与功能修复共用一次名额；只有明确代码错误或获准检查器的有效反例才修。归因和完整RTL在同一请求中返回，
checker可疑或题意未定不改稿。首稿未形成时最多一次rescue，且服务已返回有效响应；rescue取消构造和正常修复。
归因决策可使用JSON代码块或唯一裸JSON前缀；`rtl_error`之后必须紧跟唯一完整Verilog代码块。
两种形式执行相同字段与RTL校验，拒绝重复键、额外正文、多个对象/代码块和截断，不补猜决策。
HTTP结束未确认时不追加请求，已有候选继续保留。
服务返回过深JSON或不能编码为UTF-8的字符串时，客户端保留原始响应并返回可处理的模型错误；
已收到响应的确认状态和可靠usage仍保留，缺失usage仍记未知。不能用HTTP成功代替有效正文。

候选模块声明无法被接口解析器读取时，接口结果仍是`error/unknown`，但允许编译器提供进一步诊断。
只有明确的编译代码错误才能进入已有的一次修复；公开接口解析失败和确定的接口不匹配仍按原规则阻断编译。
编译、综合成功不能把未解析接口变为通过：这类候选不执行功能采样，无法验证接口的子稿不晋升。
最终结果单独给出`interface_verified`，接口解析异常时`structural_passed`为false。

使用 `AGENT_CONFIG=config/adaptive_verify.yaml ./run.sh <input> <output>`；HIP服务使用 `config/adaptive_hip.yaml`。
新预设默认连接真实服务，服务、模型和medium声明须在实验副本中核对。默认总时限9600秒、收尾120秒，没有研究模式。
`params` 使用工作流的 `AdaptiveParameters` 严格校验，可调整阶段限额；阶段额度必须连同后继预留一起放入剩余工作时间。

最多7次completion、200704输出tokens，包含思考。首次工具组300秒，修稿工具组600秒。
七阶段时间上限7380秒，加两组工具和收尾共8400秒；9600秒预设留1200秒准备裕量。
首次构造/复核、修订、重新复核分别预留5700/4500/3300/2100秒后继；RTL修复预留600秒复检。
首次复核直接批准的正常路径仍最多5次completion，未用额度不额外发请求。
实际上下文不足时仍裁剪输出，32768上下文无法为非空输入同时提供32768输出。
不按一次短请求TPS裁低输出，不使用旧辅助阶段的绝对出口或隐藏重问；上下文和全题截止仍生效。
旧三条工作流和默认配置保持原样。宽预算实验不能当作符合900秒赛事预算的成绩。

自动Skill至多两个，知识总额8192 tokens；修复的精确lint/synth诊断卡优先装配。各段完整加入或省略，
不截掉限制条件。checker不消费Skill、诊断卡、候选或实际输出。公开接口未解析完整时先记录原因并走结构检查，避免必然失败的构造调用。

full日志的 `adaptive/` 保存分析/路由、请求额度、构造及复核、逐候选assessment、修复证据和选稿理由。
`checker-draft`和`checker-initial-review`保留初版，`checker-revised-draft`和`checker-revised-review`保留修订版；
`checker-revision`记录父哈希、修订绑定及请求状态。`frozen-checker`是最近一次实际完成的复核，
重新复核未得到响应时仍可能是原拒绝结果，不能把该文件存在当作批准；最新阶段状态见`result.checker_status`。
修复提示保留反例与有限历史；完整reset到失败轨迹保存在采样产物，压缩提示时明确omitted事件，不补造观测值。
结果分别给出交付、结构、声明检查、覆盖范围及未覆盖项，`semantic_completeness_proven`始终为false。
流程完成、局部性质通过及官方正确率是不同结论。

## 采样与解释

`agent/rtl/observation.py` 接收只含公开端口、静态输入和时钟事件的 SamplingPlan。每个 case 使用独立 DUT，
`pre` 在输入驱动稳定后、有效沿前采样，`post` 在有效沿及非阻塞赋值稳定后采样。两相位都保存实际输入和输出，
包括未知位掩码、候选哈希、采样计划哈希和独立 execution_id。缺行、重复、错宽度、错相位或驱动值不符都不能记为完成。
`TraceRun.complete` 仅表示得到完整轨迹，不代表功能通过。Vivado退出0也须检查实际采样及完成标记。
`observation.validate_trace()` 是两条解释路线共用的结构化记录校验入口，核对身份、每个case的顺序、
时钟计数、采样标记、端口位宽和实际驱动值；不同case可以交错输出。日志解析保留完成标记检查，
并复用相同的行校验。解释器直接消费结构化记录，不再生成临时日志文本后重新解析。

最多8个case，总共256个事件；时序case最多32个事件，组合case最多256个。只支持组合或单时钟，
输入必须每事件完整显式驱动，不根据 DUT 输出动态生成激励。公开接口必须能确定端口方向和宽度。

公开接口解析保留已有端口列表，另支持明确的Inputs/Output章节及Design Signature顶层声明。
参数宽度只计算同声明中有界整数默认值，不执行表达式代码；已有列表可由同名端口的明确位宽说明补齐。
矛盾、半截清单、未知参数、辅助模块或bugfix正文都不能补猜为完整接口；候选接口解析器不因此改变。

`adaptive_execute.evaluate_model()` 将同一中立轨迹的post输出交给既有行为比较器，保持定宽算术与未知位。
行为比较器的`compare_trace_rows()`也供旧日志解析器使用，比较计数、掩码和未知值规则只有一份实现。
期望值仍只从独立模型、输入和模型状态计算，不能读取 DUT 输出。`properties.evaluate_properties()` 使用公开端口、
有限历史与触发快照计算局部性质；两条路线都使用同一采样器，不重复运行另一套测试台。

## 局部性质

每条性质包含公开原文依据、触发条件、采样相位、响应窗口、断言和可选的有依据abort（取消条件）。
past和窗口最多16个有效边沿，表达式使用定宽AST（抽象语法树），不支持任意Python、内部信号、跨时钟历史或动态队列。
每次触发独立计数；同一响应可能满足多个窗口，因此不证明事务一对一匹配。

报告分别保存 satisfied、violated、unknown、incomplete、aborted、untriggered。
未知触发不是false、缺历史不是零、未结束窗口和零触发都不能通过。
时钟性质只在有效沿求值，无边沿即时异步复位不在该解释器覆盖内；中立采样虽能记录这种事件，也不能据此宣称性质已检查即时复位。
局部性质通过只证明声明的检查通过，不证明题目所有功能正确。

## 验证边界

`adaptive_check` 提供构造、复核和一次拒绝修订的纯契约。构造仅接收公开TaskSpec、原文引用目录和DSL schema，
不读取候选、实际输出、Skill或求解分析。客户端严格解析JSON，拒绝截断、重复键、未知字段和越界表达式；
检查器及复核JSON中的不可编码Unicode字符串、非有限数值同样作为无效回复处理。日志以可读转义保留
异常字符，不丢弃字符或据此批准检查器；记录层容错不改变解析和授权规则，必需产物写入失败仍明确报错。
紧凑静态sequence/exhaustive在宿主展开后重新检查。行为模型最多8个寄存器、128个表达式节点；
提示建议控制状态不超过8个，但现有DSL不能机械证明任意编码的状态数。端口signed仍需依据原题进行语义复核。

明确的异步复位要求会触发离边采样预检。题面和引用使用相同的局部语句判断，排除
`no asynchronous reset`、`asynchronous reset isn't required`、`不使用异步复位`等否定描述；
一条复位的否定描述不会取消另一条肯定要求。肯定要求仍须有对应模型、肯定引用，以及先在非复位状态
经过时钟、再在无有效时钟沿时采样复位断言的事件。此预检只识别明确常见句式，不替代语义复核。

复核请求保留完整公开题面、checker、原文目录及关键预检摘要，省略重复的逐事件输入/掩码/签名表。
全局及逐case比较数、unknown/excluded、声明覆盖和警告仍保留；完整预检仍保存在checker-draft产物，
只精简模型请求，不裁剪冻结证据。静态预期不代表DUT实测，不要求模型重建所有预计算表。

复核只能accept/reject/unknown，必须绑定原检查器哈希和全部声明要求。只读FrozenChecker使用规范化JSON保存内容，
不能通过修改返回字典改变已审核版本。构造/复核无效不自动重问。approved仅允许主流程考虑修复，
还必须有真实采样、实际比较和有效反例；同一模型的构造与复核不构成独立正确性证明。

只有同题面、同稿、同哈希且重新校验有效的正式`reject`允许检查器修订；`unknown`、截断、无正文或
错误哈希不触发。修订输入只增加原checker和绑定拒绝意见，不增加候选、实测或求解知识。
模型返回完整checker，必须改变规范化内容，保留全部原需求ID/引用、原采样端口/时钟和每个原case的完整激励；
无变化比较补齐schema默认值，显式添加`signed:false`等默认字段不算修订；原始payload与哈希规则保持不变。
可在末尾追加有界case，不能删除、重排旧case或屏蔽旧采样。性质路线保留原性质ID及需求关联。
需要改变旧刺激/时钟的修订本轮不支持，明确回结构检查。语义变更仍经过相同严格预检，再用标准复核请求
重新审查新哈希；只要新版未获批准，就不使用它检查或修复RTL。预检日志保存父哈希和拒绝意见哈希，
重审Prompt不夹带旧复核结论；批准的新checker在RTL检查、修复和复检过程中不再变化。

`adaptive_selection` 统一判断修复准入和晋升：已归因的接口/编译/综合错误，或获准检查器的真实反例才能触发。
模型结果按冻结模型重新计算期望，逐bit核对；性质按每个触发义务核对。子稿须绑定真实父稿、不同代码哈希、
同一检查器与采样计划、独立执行身份，并通过必要结构检查及综合。
功能修复至少消除一个旧失败，保留全部旧通过项，不新增失败/unknown/未完成窗口；失败义务消失或被abort不算改善。
结构修复必须消除旧代码阻断，已有功能证据同样不能退步。公开接口未验证及残余功能失败分别报告。
采样器编译/展开时明确归因于候选代码的错误也属于结构修复触发，不能因尚无功能轨迹而漏掉。
采样结果与其解释结果共享同一个真实execution_id；这不代表执行了两次工具。父子候选仍必须独立重新采样。

组件已用自编正确例和错误反例进行真实Vivado采样，覆盖DFF修复后同计划复检、signed、扩宽和复位时序；
模型适配器对未知、掩码及零比较保留既有结果。运行资料留在开发区，不进入方案包。
这些是机制验收，不是实际模型构造质量、官方成绩或目标GPU环境验收。
