## 每篇的结构

```markdown
# 000X <主题>

| 状态 | 记录日期 | 最后更新 | 相关文件 | 相关数据／失败 |

## 结论（最新）      ← 一屏读完；只写当前有效的结论
## 对比表            ← 横向对比用表格；每行注明来源运行编号
## 依据              ← 按**主题**组织，不按日期堆叠
## 未决问题          ← 待定项 + 卡在哪
## 变更记录          ← 一行式：日期 + 改了什么（要追溯旧版本就写 commit）
```

四条要求：

1. **表格先行。** 先让读者能横向对比（候选、后端、方案），再给结论与推理。
2. **只保留最新结论。** 被推翻的说法直接删掉，**不要**写「以前以为……现在改为……」，
   也不要保留整段「已被取代，保留备查」的内容——那些在 git 里。
3. **历史靠 git + 变更记录。** 需要追溯时，在「变更记录」里写明旧版本所在的 commit
   （`git show <commit>:<路径>`）。每个数字都要注明来源运行编号（开发规范第 3.4 节）。
4. **复盘与细节放 `notes/`。** 决策文档只留结论、对比表与推理要点；实验过程的细节指向
   `../notes/` 与 `../experiments/`。

## 推翻或作废一个决定时

- **局部修正**（结论微调、数据更新）：直接改本文，并在「变更记录」加一行；
  **不要**把旧结论留在正文里。
- **整体作废**（不再是我们的方向）：另起一篇新编号，把旧篇状态改为
  「已作废（被 000X 取代）」，正文精简为「结论 + 指向新篇」——**不要**保留长篇旧推理。
