# agent 修复的净收益被两件事吃掉

## 现象

四个候选的联合跑分（`quick` 34 题，冻结探针 `probe-v0`）都呈现同一个形状：
**L0 明显减少，但 `S_a` 只涨一点点。** 原因是两个互相独立的损耗：

1. **修好的 L0 大多只到 L1**（能编译、仿真仍失配，系数 0.2），不是 L3。
2. **agent 会把基线本来做对的题改坏**，每轮重写整份文件。

| 候选 | L0 变化 | 变好 | L0 修好后到 L3 的比例 | L1→L3（真正的功能修复） | 变差 | 题集得分变化 | 增益 |
| --- | --- | ---: | ---: | ---: | ---: | ---: | ---: |
| A6 4B BF16 | 11 → 2 | 12 | 3/9 = **33%** | 3 道 | 2 | 0.371 → 0.518 | 1.397 |
| A5 30B-A3B AWQ-4bit | 5 → 3 | 8 | 2/3 = 67% | **5 道** | 3 | 0.594 → 0.700 | 1.178 |
| A7 CodeV-R1-7B BF16 | 4 → 0 | 6 | 1/4 = 25% | 2 道 | 2 | 0.718 → 0.765 | 1.066 |
| Q1a 4B AWQ-4bit | 12 → 6 | 9 | 3/8 = 38% | 1 道 | 3 | 0.412 → 0.471 | 1.143 |

（A7 最能说明问题：它把 4 道 L0 **全部清零**，却只有 1 道真的到了 L3，另外 3 道落在 L1。）

## 证据

- `../runs/20260925-181040-joint-Q1a-4b-awq4-quick/`（Q1a）
- `../runs/20260925-182514-joint-A6-4b-bf16-quick/`（A6）
- `../runs/20260925-183849-joint-A5-30b-2507-awq4-quick/`（A5）
- `../runs/20260925-184802-joint-A7-codev-r1-7b-quick/`（A7）

每个运行目录下：

- `<模式>/<题目>/s1/trace.jsonl`：每一轮的模型调用、接口检查、lint、综合的返回码与摘要，
  能看出「第几轮被改坏」
- `<模式>/<题目>/s1/solution.v`：最终代码；与 `baseline/<同题>/s1/solution.v` 对比即可看到重写
- `<模式>/<题目>/s1/verdict.json`：失配数
- 逐题对比用 `python3 dev/eval/compare.py <运行编号> <运行编号> --mode baseline=agent`

## 原因

### 1. 每轮重写整份文件（`../README.md` 第 7 节第 2 条）

agent 在报错后把「上一版代码 + 报错」一起发给模型，让模型**重新输出完整的文件**，
而不是做局部修改。第 1 轮已经写对的题，第 2、3 轮被整个推翻，于是出现
`Prob069_truthtable1`、`Prob122_kmap4` 这类 **L3 → L0** 的倒退。

典型例子（A5）：`Prob058_alwaysblock2`、`Prob003_step_one`、`Prob063_review2015_shiftcount`
三道基线 L3 的题在 agent 之后分别掉到 L0、L1、L1。

### 2. 报错只暴露「能不能编译」，修好它不等于功能对

`lint`（xvlog + xelab）能报出语法与详细描述错误，agent 据此改对之后，**代码只是能编译**。
功能是否与参考实现一致，agent 没有任何手段判断（参考测试台不下发，
见 `sim-mismatch.md`）。所以 L0→L1 是这条路径的**主产物**，L0→L3 只是附带。

### 3. 没有任何「保留最好版本」的机制

现在每轮的产物无条件覆盖 `best`，第 3 轮比第 1 轮差也照发。综合通过的版本会被接受，
但**综合通过 ≠ 仿真通过**，所以「接受」这个动作并不能挡住上面那类倒退。

### 4. 第 3 轮几乎不产出正确答案（四个候选一致）

把 agent 侧的样本按「实际用了几轮」分组，看其中有多少是 L3：

| 候选 | 1 轮 | 2 轮 | 3 轮 |
| --- | --- | --- | --- |
| A6 4B BF16 | 11/24 = 46% | 2/6 = 33% | 1/4 = **25%** |
| A5 30B-A3B AWQ-4bit | 21/29 = 72% | 1/1 = 100% | 0/4 = **0%** |
| A7 CodeV-R1-7B BF16 | 23/32 = 72% | 1/2 = 50% | 没有用到 3 轮 |
| Q1a 4B AWQ-4bit | 12/21 = 57% | 1/5 = 20% | 0/8 = **0%** |

**第 3 轮合计 15 个样本里只有 1 个是 L3。**

要注意这里有选择偏差：需要更多轮的题本来就是更难的题，所以「轮数多 → 正确率低」本身
不奇怪。但有两个推论仍然成立：

1. **第 3 轮的边际收益接近零**，而它要花掉一次完整的生成 + 一次综合（几十秒）。
   把这部分预算换成「多生成几个候选再挑」可能更划算（计划第 3.2 节的差分投票思路）。
2. 结合第 1、2 条损耗，**第 2、3 轮的重写在统计上是偏负面的**：它会推翻已经写对的版本，
   而它自己产出正确答案的概率又不高。

## 尝试过的办法

**到目前为止没有改过 agent。** `probe-v0` 是主分支 `2d43fc0` 上那份原版，
四个候选都是在同一个探针下测的，这样模型之间的比较才成立（见
`../decisions/0002-model-choice.md`）。所以这一节暂时是空的——这是记录，不是辩解。

计划里提过、但还没实现的做法（`../notes/2026-09-25-model-screening-plan.md` 第 3.2 节）：

- 在上一版基础上局部修改（patch），而不是重新生成
- 多份候选做差分仿真后投票
- 让模型自己写激励或参考模型做自验证

## 为什么值得优先做

1. **不需要换模型、不需要新工具**：把「重写整份文件」改成「局部修改」就能直接少丢 2–3 道题，
   而四个候选上这个损失都是一样的。
2. **它同时改善分子和分母之外的东西**：这些题本来就在基线里算对了（L3 = 1.0），
   被改坏等于白送分，是纯粹的净损失。
3. **它决定了模型选型的结论**：小模型的低基线主要来自语法错误，而修语法只值 0.2 分
   （见 `sim-mismatch.md`）。不解决这两处损耗，「低基线 + 高增益」这条路走不通。

## 下一步

1. 把修复改成局部修改，并加一条「保留历史最好版本」的兜底（按等级选，而不是按轮次）。
2. 用同一个 `quick` 34 题、同一批候选复测，直接看「变差」列是否归零。
3. 顺便试一次「把第 3 轮换成第 2 个候选」：同样的时间预算下，多生成一份新答案再挑，
   和再改一版，哪个更划算（见上面第 4 条：第 3 轮的边际收益接近零）。
4. 之后再谈功能自验证——那才是把 L1 推向 L2/L3 的手段。

**注意**：任何改动都会让 `probe-v0` 失效，所以改完之后四个候选都要重跑一遍，
不能拿新 agent 的结果和现在的数字混在一张表里比。
