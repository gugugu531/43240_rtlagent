**这是方案第一次真正被测。** 之前 14 次运行全是 `baseline` 或 `reference`，`S_a` 一次都没有过。
本次用冻结的探针 `probe-v0`（主分支 `2d43fc0` 上的 agent 代码，本轮未改动）跑
`--modes agent,baseline`，题集是 `quick` 34 题，两者在同一次运行中产出，满足
`SCORING.md` 第 3.2 节「分子分母同一次运行」的要求。

环境同 `2026-09-25-screening-results.md`（W7900，vLLM 0.16.1.dev0，实例模板 4443）。

## 三个结论（都很重要）

### 1. 确定性检查有效，L0 直接减半

L0 从 12 道降到 6 道。这和「语法、详细描述、接口三类错误有确定依据可修」的判断一致：
agent 的 `check_interface` 与 `lint` 确实把这一类救回来了一半。

### 2. 但「能编译」不等于「功能对」——修好的 L0 大部分停在 L1

9 道变好的题里，只有 **4 道真正到了 L3**，另外 **5 道停在 L1**（能编译、仿真仍然失配）。
也就是说 L0 → L3 的转化率只有约 **44%**。

**这一条推翻了我在 `../failures/sim-mismatch.md` 里做的上限估算。** 那个估算假设
「修好 L0 就直接落到 L3」，据此算出 `Qwen3-4B-Instruct-2507`（AWQ-4bit） 的 `S_a` 上限 0.711、增益 2.07 倍。实测的
路径是 L0 → L1（系数只有 0.2），所以真实上限低得多：本次拿到的增益只有 **1.143**。

### 3. agent 会把本来做对的题改坏——3 道（占基线 12 道 L3 的 25%）

`Prob069_truthtable1`、`Prob122_kmap4` 从 L3 掉到 L0，`Prob032_vector0` 从 L3 掉到 L1。
这直接吃掉了 9 道变好的收益（约 −0.07 的题集得分）。

很可能的原因就是 `../README.md` 第 7 节第 2 条写的：**agent 每轮都让模型重写整个文件**，
而不是在上一版基础上做局部修改。第一轮已经写对的题，在第 2、3 轮被推翻重写。
这也是后续改进里收益最直接的一条——「能修」和「不破坏」要一起优化，否则净收益上不去。

## 对选型的影响

第一个数据点说明：**光靠捡 L0 拿不到多少增益**，真正的增量还是在 L1→L2/L3（功能正确性）。
因此

- 「低基线小模型」那条路**没有想象中那么划算**：它的低分主要来自语法错误，而修语法只值 0.2 分。
- 除非先解决两件事：**功能自验证**（把 L1 变 L2/L3）与**不破坏已有正确答案**（局部修改而非重写）。
- 这两个问题与模型选型是**正交**的：换模型解决不了，得改 agent。所以模型选型的紧迫性下降，
  agent 改进的优先级上升。

后续会话继续测 `Qwen3-4B-Instruct-2507`（BF16）（同模型的 BF16）、`Qwen3-30B-A3B-Instruct-2507`（AWQ-4bit）、`CodeV-R1-RL-Qwen-7B`（BF16），看「模型越强，agent 的 L1→L3 转化率是否更高」。

### 一个反直觉的对比：4-bit 伤的是「修复能力」，不是「生成能力」

| | baseline `S_b` | agent `S_a` | 增益 | 可计算分 |
| --- | ---: | ---: | ---: | ---: |
| `Qwen3-4B-Instruct-2507`（AWQ-4bit）（AWQ-4bit） | **0.4118** | 0.4706 | 1.143 | 19.95 |
| `Qwen3-4B-Instruct-2507`（BF16）（BF16） | 0.3706 | **0.5176** | **1.397** | **30.11** |

**4-bit 版的基线反而更高（0.4118 对 0.3706），但加上 agent 之后被满精度版反超
（0.4706 对 0.5176）。** 也就是说量化在这一组里表现为：

- 对**单次裸跑**：几乎没伤（与全题集上的结论一致：0.3923 对 0.3935）
- 对**多轮修复**：明显伤 —— `Qwen3-4B-Instruct-2507`（AWQ-4bit） 的 agent 把 9 道修好、也改坏了 3 道；
  `Qwen3-4B-Instruct-2507`（BF16） 修好 12 道、只改坏 2 道，而且多修好了 3 道功能错题

这支持计划 §4.1 的 **H2**（量化主要伤害「看懂报错、遵循修改指令」的能力，而不是生成能力），
不支持 H1。按这条，**最终选型在显存允许时应优先满精度或 8-bit，把 4-bit 留给装不下的模型**。

> 样本量提醒：这是 `quick` 34 题上的单次采样，1.143 与 1.397 的差距不小，但仍是单点数据。
> 结论要等 `Qwen3-30B-A3B-Instruct-2507`（AWQ-4bit）与 `CodeV-R1-RL-Qwen-7B`（BF16），以及全题集复跑之后再定。

| 候选 | `S_b` | `S_a` | 增益 | 能力分 | 增益分 | **可计算分 / 70** |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| `Qwen3-4B-Instruct-2507`（BF16） 4B BF16 | 0.3706 | 0.5176 | **1.397** | 15.53 | **14.58** | **30.11** |
| `Qwen3-30B-A3B-Instruct-2507`（AWQ-4bit） 30B-A3B AWQ-4bit | 0.5941 | 0.7000 | 1.178 | **21.00** | 7.16 | 28.16 |
| `CodeV-R1-RL-Qwen-7B`（BF16） | **0.7176** | **0.7647** | 1.066 | 22.94 | 2.78 | 25.72 |
| `Qwen3-4B-Instruct-2507`（AWQ-4bit） 4B AWQ-4bit | 0.4118 | 0.4706 | 1.143 | 14.12 | 5.83 | 19.95 |

读法：

1. **`Qwen3-4B-Instruct-2507`（BF16） 领先，而且在 `M` 的全部合理取值上都领先**（这一条修正了本文初稿的说法——
   当时我凭眼看判断「M 大时 `Qwen3-30B-A3B-Instruct-2507`（AWQ-4bit） 反超」，实际算过之后不成立）：

   | M | `Qwen3-4B-Instruct-2507`（BF16） | `Qwen3-30B-A3B-Instruct-2507`（AWQ-4bit） |
   | ---: | ---: | ---: |
   | 2.0 | **34.82** | 30.45 |
   | 2.5 | **30.12** | 28.15 |
   | 3.0 | **27.70** | 26.96 |
   | 3.5 | 26.20 | **26.23** |
   | 4.0 | 25.17 | **25.73** |

   两者的可计算分在 **M ≈ 3.48** 处交叉，也就是说 `Qwen3-30B-A3B-Instruct-2507`（AWQ-4bit） 只有在 M > 3.5 时才反超。
   `SCORING.md` 第 4.3 节的示例用 2.5，所以**按现有数据 `Qwen3-4B-Instruct-2507`（BF16） 是更稳的选择**。
   代价是它的绝对能力更低（`S_a` 0.518 对 0.700）：一旦 agent 大幅改进、把两者的
   `S_a` 都推高，这个排序还要重算——`Qwen3-4B-Instruct-2507`（BF16） 的增益涨得更快，所以改进对 `Qwen3-4B-Instruct-2507`（BF16） 反而更有利。
2. **增益随基线单调下降**（把 4-bit 的 `Qwen3-4B-Instruct-2507`（AWQ-4bit） 排除后更明显）：`Qwen3-4B-Instruct-2507`（BF16） 0.371→1.397、
   `Qwen3-30B-A3B-Instruct-2507`（AWQ-4bit） 0.594→1.178、`CodeV-R1-RL-Qwen-7B`（BF16） 0.718→1.066。这验证了计划第 1.3 节的推论。
3. **四个候选的 `S_a` 都没超过 0.77**，而 baseline 最高的 `CodeV-R1-RL-Qwen-7B`（BF16） 已经把 `S_a` 推到 0.765。
   也就是说**现有 agent 的天花板大概就在 0.7 附近**，把 `S_a` 往上推要靠 agent 本身，
   而不是换一个更强的模型——更强的模型同时抬高分母。

## 联合阶段的共同结论

- **确定性检查（接口 + lint）确实有效**：四个候选的 L0 都大幅下降
  （12→6、11→2、5→3、4→**0**）。
- **但 L0 修好不等于功能对**：L0→L3 的转化率只有约 44%–50%，其余停在 L1（系数 0.2）。
  `CodeV-R1-RL-Qwen-7B`（BF16） 最能说明问题：它把 4 道 L0 全部清零，其中 3 道只到 L1。
- **agent 会改坏本来做对的题**：四个候选分别损失 3、2、3、2 道基线 L3 的题。
  原因是每轮重写整个文件（`../README.md` 第 7 节第 2 条）。
- **真正有价值的修复是 L1→L3**：`Qwen3-30B-A3B-Instruct-2507`（AWQ-4bit） 修好 5 道、`Qwen3-4B-Instruct-2507`（BF16） 修好 3 道、`CodeV-R1-RL-Qwen-7B`（BF16） 修好 2 道、`Qwen3-4B-Instruct-2507`（AWQ-4bit） 修好 1 道。
  这类题没有任何工具能报出「错在哪」，agent 只能靠模型自己重读题面发现，
  属于模型能力而非工具能力。它也是唯一能同时抬高 `S_a` 与增益的途径。
- **换更强的模型解决不了这个问题**：`CodeV-R1-RL-Qwen-7B`（BF16） 是最强的（`S_a` 0.765），可计算分却排第三。

### 下一步的改进优先级（按预期收益排序）

1. **先解决「改坏」**：改成在上一版基础上局部修改，而不是每轮重写整份文件。
   这一条不需要换模型、不需要新工具，四个候选上都直接损失了 2–3 道题。
2. **再做功能自验证**：把 L1 往 L2/L3 推（差分仿真投票、让模型自己写激励），
   这是增益的主要来源。
3. **最后才是继续换模型**，而且要在 `M` 公布之后按可计算分定。
   目前 `Qwen3-4B-Instruct-2507`（BF16）（4B BF16）与 `Qwen3-30B-A3B-Instruct-2507`（AWQ-4bit）（30B-A3B AWQ-4bit）在 30.1 与 28.2 上几乎打平。

### 只测了 `quick` 34 题

四个候选都是 `quick` 子集上的单次采样，绝对值会比全题集高 0.06–0.08
