## 结论（最新）

### 首选：4B 方案（`Qwen3-4B-Instruct-2507`，BF16）

| 理由 | 依据 |
| --- | --- |
| **可计算分最高且是实测的** | `S_b` 0.394 + `S_a` 0.518 → 增益 1.397 → **30.1/70**（运行 `182514-joint-A6-4b-bf16-quick`） |
| **对 agent 改进最友好** | 它的分母最低，同样的 `S_a` 提升换来的增益最大；方案越做越好，选它越划算 |
| **风险最小** | BF16 权重只有 7.67 GiB，**没有量化格式风险**；32 GiB 单卡余量最大 |
| **速度够用** | 单路约 52 token/秒，比对照组 `CodeV-R1-RL-Qwen-7B`（30.0）快 |

### 挑战者：最容易翻盘的三个

判据：要在可计算分上超过 4B 方案当前的 **30.11**，该候选自己的 `S_a` 需要达到多少
（完整排序与全部指标见下面的**表 1**）：

| 候选 | `S_b` | 反超所需 `S_a` |
| --- | ---: | ---: |
| `Devstral-Small-2-24B-Instruct-2512`（AWQ 4-bit） | 0.4335 | **0.580** |
| `Qwen2.5-Coder-7B-Instruct`（BF16） | 0.4516 | **0.597** |
| `Ministral-3-14B-Instruct-2512`（AWQ 4-bit） | 0.4761 | **0.620** |

其余候选的门槛都在 0.678 以上（新一代 35B MoE 是 0.734，`gpt-oss-20b` 是 0.795，见 表 1）。
**门槛最低的既不是最大的、也不是最强的模型**——基线越高，增益空间越小，而「能力强」正好
体现在已经被计入分母的那部分。

**已有的实测锚点**：`Qwen3-30B-A3B-Instruct-2507`（AWQ 4-bit）的 `S_a` 已经做到 **0.700**，
门槛 0.716——**差一点**，最终可计算分 28.2 低于 4B 方案的 30.1。

### 采样噪声：它决定怎么读上面的表

| 测法 | 结果 |
| --- | --- |
| `Qwen3.6-35B-A3B` 同配置、quick 34 题、3 次采样（运行 `174638-repeat-quick-…`） | 0.6588 / 0.6529 / 0.7000 → 均值 0.6706，**极差 0.047、标准差 0.021** |
| `Qwen3-30B-A3B-Instruct-2507`（GPTQ-Int4）同配置、全题集、跑了两次（运行 `091939` / `091940`） | 0.5600 / 0.5845，**相差 0.0245** |

所以：

- 「中基线那一档」（0.588–0.610）之间的差距（最大 0.022）**小于实测噪声**，它们应视为**同一档**，
  不能凭单次跑分排序。要排序至少跑 3 次取均值，且差距大于约 0.04 才值得下结论。
- 门槛分析**不受噪声影响**：它比较的是各候选自己的 `S_b` 与 4B 方案的 `S_b`，都是全题集单次测量，
  口径一致。

### 需要团队拍板的两条口径

1. **`M`（满分线倍数）未知**：M 越小越有利于低基线方案。`Qwen3-30B-A3B-Instruct-2507` 反超
   4B 方案需要 M > 3.48；`SCORING.md` 的示例值是 2.5。
2. **决赛硬件未验证**：35B MoE 方案在 32 GiB 上要用约 90% 显存，且 **MoE 在 gfx1201 上无人验证**；
   4B 方案这两条风险都小。

### 建议的下一步

联合阶段（`--modes agent,baseline`）先测门槛最低的两个：**`Devstral-Small-2-24B`** 与
**`Qwen2.5-Coder-7B-Instruct`**（都很快很稳）。注意这只是「谁更容易翻盘」的排序，
不代表谁更强。

## 依据

### 1. 为什么「低基线」是决定性的

评分里可计算的部分是 `30·S_a + 40·min(1, ln(增益)/ln M)`，增益 = `S_a / S_b`。
分母（基线）越低，同样的 `S_a` 提升换来的增益越大；而「模型能力强」正好会**同时抬高分母**——
能力越强，一次性裸跑就越准，增益空间越小。4B 方案的 `S_b` 0.394 是候选里最低的那一档，
这就是它领先的根本原因。

这条不是推理，有实测锚点：`Qwen3-30B-A3B-Instruct-2507`（AWQ-4bit）的 `S_a` 已经做到 0.700，
仍差自己门槛 0.716 一点，可计算分 28.2 < 30.1。

### 3. 服务与口径（会影响分数的可比性）

- **思考开关**：混合思考模型必须服务端关闭，否则基线被截断主导
  （[`../failures/thinking-in-content.md`](thinking-in-content.md)）；
  `gpt-oss-20b` 默认即无思考，已实测确认。
- **量化格式**：AWQ 需要 `--dtype float16`，但 MLA 类模型不能加；MoE 要求对称量化且组大小 ≠ 16
  （[`../failures/serving-stack.md`](serving-stack.md)）。
- **显存**：`gpu_memory_utilization` 按「权重 + KV + 开销」定，本项目统一用 0.85；
  `max_model_len` 统一 32768。

### 4. 被排除的候选

| 候选 | 排除理由 |
| --- | --- |
| `Qwen3.8-27B` | HF 上没有 4-bit 量化版本，只有官方 FP8（27.78 GB）与 ROCm 用不了的 NVFP4 |
| `North-Mini-Code-1.0` | 试过五个量化版本，当前服务栈没有可用格式（`symmetric: false`、组大小 16 被判成 NVFP4、`auto-round` 未注册、`inc` 在 ROCm 被拒） |
| `granite-4.2-30b` | IBM 只发布 fp8 / mxfp4 / nvfp4，三种在本栈上都不可用；没有社区 4-bit |
| `DeepSeek-Coder-V2-Lite-Instruct` | 社区只有 FP8 与 w8a8；BF16 装不进 32 GiB |
| `GLM-4.7-Flash`、`Kimi-Linear-48B-A3B` | 自带分词器代码与 transformers 5.15 不兼容（`bytes_to_unicode`） |
| `Seed-OSS-36B-Instruct` | 能服务但 dense + AWQ 在这张卡上只有 3.25 tps，118/155 请求超时 |
| `Qwen3.6-27B`（dense） | 分数 0.610 不低，但单路只有 4.9 token/s，agent 每题多次调用跑不动 |
| `Qwen3-Coder-30B-A3B` | 基线 0.5639，又没测过 `S_a`，被同档的 `Qwen3-30B-A3B-Instruct-2507` 与 35B MoE 覆盖 |
| `Qwen3.6-27B-AWQ-6Bit` | 仓库名写 6Bit，但 `config.json` 里是 `awq`/`bits: 4` 且无 `config_groups`，精度存疑；dense 又已因速度出局 |
