# Qwen3 思考模式输出额度补测

类型：实验设计与验证记录。状态：实现已验证，云端补测进行中。日期：2026-10-11。
来源：用户在 Qwen3 云端筛选过程中要求放宽思考模式输出上限并保留日志。

## 观察与假设

运行 `20261011-142353-qwen3-4b-awq-think-full34-4f3ab9b5` 在 34 题中有 15 次
`finish_reason=length`，这些回复只有思考文本，没有最终代码。原始配置使用 baseline 的
8192 token 上限。增加输出额度可能让部分题目完成推理，但反复重复的回复也可能继续截断。

## 实验边界

- 保留所有原始结果，单独重跑思考模式中实际截断的题目。
- 补测输出上限为 32768，模型服务上下文为 36864，KV cache（注意力键值缓存）为
  6000000000 字节；请求超时最多 900 秒，整题预算 960 秒。
- 原始题面、系统提示、温度 0、top_p=1 和 baseline 代码提取保持不变。
- 显式导入 `agent.workflows.single_generate_long_output` 并选择
  `single_generate_long_output`；默认 `single_generate` 和 `repair_loop` 不变。
- `baseline.py` 与 `run_baseline.sh` 不作修改，也不修改其进程内常量。
- 保留完整请求、响应、思考文本、候选、trace、判定和资源日志。新增
  `experiment_override` 事件标明额度覆盖。
- 仍采用 24000000000 字节的 PyTorch 分配预算和每 0.1 秒采样的 28000000000 字节整卡
  提前停止阈值，为用户要求的 32000000000 字节上限保留余量。采样峰值不代表硬件分区保证。

## 验证

`python3 -m unittest discover -s dev/tests -p 'test_*.py'`：134 项测试，2 项按既有条件
跳过，其余通过。新增差分检查确认补测请求体只改变 `max_tokens`，默认节点之后仍使用
8192；超时遵循剩余预算。现有 baseline 差分和 repair_loop 回归通过。

正式 `run.sh` 入口的 mock smoke 记录到 32768 token、900 秒，并正常提取、选择与保存代码。
`dev/tools/submission.py` 检查及不含 dev 的运行包 smoke 通过；该运行包的长输出扩展也通过。

首次 smoke 将运行扩展放在开发区，受到运行时导入边界检查拒绝。按规范移至
`agent/workflows/` 后重测通过，失败记录保留。该扩展没有参考答案或判定器依赖。

## 结果解释

补测属于输出额度对照，不算严格 baseline 请求等价结果。报告同时给出原始截断数、恢复最终
内容的数量、最终 L3 通过数量、仍截断数量、实际 token 和耗时，并检查新旧思考文本前缀。
仅针对截断题的补测得分不能直接与完整 34 题得分比较，也不能当作完整题集的一次生成成绩。
