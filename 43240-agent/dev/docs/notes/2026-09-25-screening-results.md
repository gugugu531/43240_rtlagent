## 两个必须先记下来的环境发现

### 1. 这个 vLLM 不认 2026 年的新架构

`transformers 4.57.6` 与这份 vLLM 的架构注册表里都**没有 `qwen3_5` / `qwen3_5_moe`**，
所以 **`Qwen3.6-35B-A3B`（AWQ-4bit）（Qwen3.6-35B-A3B）、`Qwen3.5-35B-A3B`（AWQ-4bit）（Qwen3.5-35B-A3B）、`Qwen3-4B-Instruct-2507`（BF16）（Qwen3.5-9B/4B）、`Qwen3.8-27B`（Qwen3.8-27B）
本次全部无法测试**。注册表里可用的相关架构是 `Qwen3MoeForCausalLM`、`Qwen3ForCausalLM`、
`Qwen2ForCausalLM`、`GptOssForCausalLM`、`Glm4MoeLiteForCausalLM`。

要测这几个模型，要么换更新的镜像／模板，要么在实例上另建一个虚拟环境装更新的 vLLM
（风险：ROCm 轮子要与 torch 2.9.1 + ROCm 7.2 对得上）。

### 2. AWQ 必须显式指定 `--dtype float16`，否则起不来

`cyankiwi/Qwen3-30B-A3B-Instruct-2507-AWQ-4bit` 的量化分组是 **group_size=32**，
默认（bf16 激活）下 vLLM 找不到可用的 WNA16 线性层实现，直接报：

```
ValueError: Failed to find a kernel that can implement the WNA16 linear layer. Reasons:
 ConchLinearKernel cannot implement due to: Group size (32) not supported ... supported group sizes are: [-1, 128]
 ExllamaLinearKernel cannot implement due to: Exllama only supports float16 activations
```

加 `--dtype float16` 后选中 `ExllamaLinearKernel`，正常加载。**只影响激活精度，不影响权重
量化方式**，但要在 `MODEL.md` 里如实写明。这条要写进
[`../decisions/0001-inference-backend.md`](0001-inference-backend.md)。

### 3. gpt-oss-20b（`gpt-oss-20b`（原生 MXFP4））在当前镜像里跑不起来

模型能加载（权重 14.3 GiB，KV 池 284,400 token），但启动推理服务时报：

```
openai_harmony.HarmonyError: error downloading or loading vocab file
```

`openai_harmony` 的 Rust 分词器（tiktoken-rs）在运行时要去
`https://openaipublic.blob.core.windows.net/encodings/o200k_base.tiktoken` 取词表，
而平台的出口代理对这个域名返回 **403**（只放行 HF 与 PyPI 镜像）。镜像里也没有预置这份词表，
HF 的 `openai/gpt-oss-20b` 仓库里也没有这个文件。

两条可能的修法，留待后续会话验证：

1. 给 `TIKTOKEN_ENCODINGS_BASE` 指一个可达的镜像地址（需要有一个放这份文件的来源），
   或按 sha256 `446a9538cb6c348e3516120d7c08b09f57c36495e2acfffe59a5bf8b0cfb1a2d`
   预先把文件塞进 `TIKTOKEN_RS_CACHE_DIR`（默认 `tiktoken-rs-cache`）。
2. 在自制镜像里预置该词表——**这也是提交时必须做的**：决赛沙箱断网，这条路必须在
   Dockerfile 里解决，否则 gpt-oss 系列一律按 L0 计。

### `CodeV-R1-RL-Qwen-7B`（BF16） 印证了选型计划里的那条判断

CodeV-R1-7B 是目前 baseline 最高的候选（0.665），而且强得很有特点：计数器/定时器 1.000、
组合逻辑 0.898、移位寄存器 0.840，但**卡诺图与真值表只有 0.150**。

这正好是 `2026-09-25-model-screening-plan.md` 第 1.2 节说的那类模型：一次性裸跑很强，
于是增益的分母被抬高、空间被压缩。它的增益上限是 `1 / 0.665 = 1.50` 倍，按 M = 2.5 折算
增益分最多 18.0；而 `Qwen3-30B-A3B-Instruct-2507`（AWQ-4bit） 的增益上限是 `1 / 0.588 = 1.70` 倍。**是否选它，取决于 agent 能把
两者分别抬到多高**，这要等联合阶段的数据。

另一个细节：它是唯一一个「输出 token 数中位数很低（307）但最长到 6315」的模型——
说明它平时直接给答案，少数题会进入长思考。它的并发 1 解码速度只有 30.0 token/秒，
约为 `Qwen3-30B-A3B-Instruct-2507`（AWQ-4bit）（74.7）的 40%，慢得多。


### `Qwen3-4B-Instruct-2507`（BF16）（4B BF16）是目前基线最低的候选，正好用来检验「低基线」那条路

`S_b = 0.394`，比之前记录的最低值（Qwen3-8B 关思考 0.415）还低。它的增益上限是
`1 / 0.394 = 2.54` 倍——**已经超过 M = 2.5 的示例满分线**，也就是说只要 agent 能把它抬到
接近满分，增益项就能拿满 40 分。

代价是能力项：它的裸跑可综合率只有 0.316，要抬到 0.75 以上才谈得上划算。这正是
`2026-09-25-model-screening-plan.md` 第 1.3 节那张表说的情形，必须等联合阶段的数据才能定。

另外它有 **6.5% 的输出被截断**（10 个样本），是这批候选里唯一一个截断率上千分之几的——
小模型的输出更长更啰嗦，撞上 `baseline.py` 的 8192 上限。这一条属于服务配置风险，
但它恰好是 §5.2「截断导致的 L0」那一栏的真实样本。

### `Qwen3-30B-A3B-Instruct-2507`（AWQ-4bit） 与之前那次 0.489 的差别

之前测的 `Qwen3-30B-A3B-GPTQ-Int4`（原始版本、关思考）是 **0.489**，这次
`Qwen3-30B-A3B-Instruct-2507` 的 AWQ 版本是 **0.588**。两者相差 0.1，可能来自三处，
本轮没有做单变量隔离，不能直接归因：模型版本（2507 是改进版）、量化方式（AWQ vs GPTQ）、
以及 `--dtype float16`（激活精度）。如果要写进报告，需要补一组对照实验。

## 量化对照（计划 §4.2 的 量化对照组 1）：同一个 4B 模型的三个精度

选 `Qwen/Qwen3-4B-Instruct-2507` 做这一组，因为它 BF16 直接装得下，可以干净地隔离
「精度」这一个变量——同一模型、同一尺寸、同一分词器、同一个量化作者。

| 精度 | `S_b` | 等级分布 L0/L1/L2/L3 | 权重显存 | KV 池 | **tps（并发 1）** |
| --- | ---: | --- | ---: | ---: | ---: |
| BF16 | **0.3935** | 46/60/0/49 | 7.67 GiB | 145,888 token | 52.0 |
| AWQ 8-bit | **0.3923** | 43/64/0/48 | 5.41 GiB | 162,672 token | **99.3** |
| AWQ 4-bit | **0.3432** | 57/56/0/42 | 3.45 GiB | 175,136 token | 34.7 |

（三次跑分的 `rocm-smi` 峰值都在 30.0–30.3 GiB，因为 `gpu_memory_utilization=0.62` 把预算
填满了，和权重多大无关。要比显存占用必须看「权重」那一段，不能看总峰值。）

### 三个结论

1. **8-bit 是这张卡上的甜点。** 质量与 BF16 在噪声范围内相同（0.3923 对 0.3935，差 0.001），
   显存少 2.3 GiB，**速度接近翻倍**（99.3 对 52.0 token/秒）。
2. **4-bit 明显掉分**：0.3432，相对 BF16 低 12.8%，而且**它是三者里最慢的**。
   原因是 4-bit 走 `ExllamaLinearKernel`（必须 fp16 激活，见本文开头第 2 条），
   比 8-bit / BF16 的原生路径慢。
3. 所以「4-bit 就是更快更省」在这张卡上**不成立**。4-bit 只在**装不下**的时候才有意义
   （例如 30B 级 MoE：AWQ 4-bit 权重 17.54 GiB，BF16 要 61 GiB）。这条要写进
   `MODEL.md` 和设计报告里的模型选择理由。

对计划 §4.1 三条假设的影响：H3（低精度换来更多轮数抵消精度损失）**目前不成立**——
4-bit 既掉分又更慢。H1、H2 还要等联合阶段的 `S_a` 才能判。

> 注意样本量的限制：`S_b` 的差 0.001（8-bit 对 BF16）在 155 题上的标准误量级之内，
> 不足以宣称「8-bit 与 BF16 完全等价」；但 0.05 的差（4-bit 对 BF16）远超噪声。

### 下一步建议

1. **先解决架构支持**，否则最有价值的几个候选（`Qwen3.6-35B-A3B`、`Qwen3.5-35B-A3B`、`Qwen3.8-27B`，以及计划里的 `Qwen3.5-9B`）

   PR #48081 被关闭且未合并，社区改用手工补丁；而实例上 pip 装新版 vLLM 受代理限制，
   很可能走不通。优先换镜像：平台列表里有一个 `Qwen3.8-27B` 的镜像，能跑它说明其

   [`../failures/serving-stack.md`](serving-stack.md)。
2. **`gpt-oss-20b`（原生 MXFP4） 的词表问题必须在镜像里解决**：决赛断网，`openai_harmony` 又要在运行时取
   `o200k_base.tiktoken`，不预置就一律 L0。这条不是「能不能测」的问题，是「能不能提交」的问题。
3. 拿到 `S_a` 的前提是先有一个冻结的 agent。**先筛选、后联合**的路线已经走过筛选阶段，
   下一步该把入围名单定下来、开始联合跑分（计划 §7.2 的第 4、5 步）。
4. 入围初判改为看**结构上限**（只修好语法/详细描述/接口三类 L0 时的 `S_a` 上限，
   算法与数据见 [`../failures/sim-mismatch.md`](sim-mismatch.md)）：
   `Qwen3-4B-Instruct-2507`（AWQ-4bit） 4B-AWQ4 上限 0.711（增益 **2.07** 倍）、`Qwen3-4B-Instruct-2507`（BF16） 4B-BF16 上限 0.690（1.75 倍）、
   `Qwen3-30B-A3B-Instruct-2507`（AWQ-4bit） 上限 0.730（1.24 倍）、`CodeV-R1-RL-Qwen-7B`（BF16） 上限 0.729（1.10 倍）、`Qwen3-Coder-30B-A3B`（AWQ-4bit） 上限 0.674（1.19 倍）。
   **上限分（`30·S_a + 40·ln(增益)/ln(2.5)`）粗算：`Qwen3-4B-Instruct-2507`（AWQ-4bit） ≈ 53、`Qwen3-4B-Instruct-2507`（BF16） ≈ 45、`Qwen3-30B-A3B-Instruct-2507`（AWQ-4bit） ≈ 31、`Qwen3-Coder-30B-A3B`（AWQ-4bit） ≈ 28、`CodeV-R1-RL-Qwen-7B`（BF16） ≈ 26。**
   建议入围联合阶段的是 **`Qwen3-4B-Instruct-2507`（BF16）、`Qwen3-4B-Instruct-2507`（AWQ-4bit）、`Qwen3-30B-A3B-Instruct-2507`（AWQ-4bit）、`CodeV-R1-RL-Qwen-7B`（BF16）** 四个（`Qwen3-4B-Instruct-2507`（BF16） 与 `Qwen3-4B-Instruct-2507`（AWQ-4bit） 是同一模型的两种精度，
   合起来正好验完「低基线路线」与「量化是否提高增益」两个问题）。

**为什么要测 `Qwen3.6-27B`（AWQ-4bit，dense） 而不是 `Qwen3.8-27B`**：`Qwen3.8-27B`（`Qwen/Qwen3.8-27B`）在 HF 上**没有 4-bit 量化版本**，
只有官方 FP8（27.78 GB）与 NVFP4（ROCm 不可用）；FP8 的 27.78 GB 权重加 KV 后放不进
32 GiB 单卡，所以它无法成为最终选择。于是用同代的 dense 27B AWQ 顶上，代表「dense 路线」。

**dense 27B 的致命问题不是分数而是速度**：

| | `Qwen3.6-35B-A3B` / `Qwen3.5-35B-A3B`（都是 35B MoE） | `Qwen3.6-27B`（AWQ-4bit，dense） |
| --- | ---: | ---: |
| 单路解码（并发 1） | 50.8 / 55.4 token/s | **4.9 token/s** |
| 单题耗时 中位数 | 8.4 / 6.7 s | **28.8 s** |
| 单题耗时 p90 | 101 / 48 s | **182.8 s** |
| 模型请求失败 | 8 / 5 | **11** |

分数三者几乎一样（0.610 / 0.605 / 0.610），但 dense AWQ 在这张卡上慢了十倍，
请求超时（`baseline.py` 的 300 秒上限）造成的 L0 也最多。
**这条基本可以替 dense 路线判死刑**：agent 每题要多次调用，4.9 token/s 根本跑不动。

**`Qwen3.6-35B-A3B`（AWQ-4bit） 与 `Qwen3.5-35B-A3B`（AWQ-4bit） 几乎打平（0.610 对 0.605）**：新一代的 Qwen3.6-35B-A3B 在 baseline 上只比
Qwen3.5-35B-A3B 高 0.005，而两者权重占用与速度也都一样（22.41 GiB、KV 池约 45–47 万 token）。
差别只在细节：`Qwen3.6-35B-A3B`（AWQ-4bit） 的 L3 88 道对 `Qwen3.5-35B-A3B`（AWQ-4bit） 的 86 道，`Qwen3.5-35B-A3B`（AWQ-4bit） 的请求失败 5 次对 `Qwen3.6-35B-A3B`（AWQ-4bit） 的 8 次。
**如果最后要在这一档里选，两者可以视为同一档，按 L0 更少/更稳的那个选。**


**`Qwen3.6-35B-A3B`（AWQ-4bit） 的两个要注意的地方**：

1. **有 8 道题的模型请求失败**（占 5%），最长耗时正好是 `baseline.py` 的 300 秒超时上限。
   求解耗时合计 6007 s，是 `Qwen3-30B-A3B-Instruct-2507`（AWQ-4bit）（1904 s）的三倍多——p90 就有 101 s。
   慢的尾部会直接变成 L0，这是墙钟风险，不只是速度问题。
2. **它在 48 GiB 卡上跑到 37.43 GiB**（`GPU_UTIL=0.85`）。按 32 GiB 单卡折算：
   权重 22.41 GiB + 单序列 KV 约 0.64 GiB + 开销，需要 `gpu_memory_utilization ≈ 0.9` 才装得下，
   余量很小。**能不能在决赛的 32 GiB 卡上跑，必须在 R9700 上实测**。

## 重复性验证：`Qwen3.6-35B-A3B`（AWQ-4bit）quick 34 题 × 3 次采样（2026-09-27）

**为什么做这个**：全题集筛选里 `Qwen3-30B-A3B-Instruct-2507`（0.588）、`Qwen3.5-35B-A3B`（0.605）、
`Qwen3.6-35B-A3B`（0.610）、`Qwen3.6-27B`（0.610）挨得很近（最大差 0.022），而所有分数都是**单次采样**，
没有噪声尺度就无法说谁更好。计划第 5.2 节也要求分差小时必须重复。

服务参数与筛选时**完全一致**（`max_model_len 32768`、`gpu_memory_utilization 0.85`、关闭思考），
日志里的 `Model loading took 22.41 GiB` 与 `GPU KV cache size: 474,273 tokens` 与筛选那次逐字相同。

| 采样 | 得分 | 等级分布（L0 / L1 / L3） |
| --- | ---: | --- |
| 第 1 次 | 0.6588 | 6 / 7 / 21 |
| 第 2 次 | 0.6529 | 7 / 6 / 21 |
| 第 3 次 | 0.7000 | 7 / 4 / 23 |
| **三次均值** | **0.6706** | 20 / 17 / 65（合计） |

**极差 0.0471，标准差 0.0209。**

### 两个结论

1. **「0.588–0.610」那一档的单次采样排序没有意义。** 同一模型、同一配置、同一子集，
   三次采样的极差就有 **0.047**、标准差 **0.021**——比那一档四个模型之间的最大差距（0.022）还大。
   所以只能说它们**同属一档**，不能凭单次跑分排出先后。要排序至少得跑 3 次取均值，
   并且差距要大于约 0.04 才值得讨论。
2. **quick 子集相对全题集的偏移得到独立验证。** 这个模型全题集（155 题、单次）是 0.610，
   quick 子集（34 题、三次均值）是 0.6706，高 **0.061**——正好落在此前记录的 0.06–0.08 区间内。
   也就是说 quick 与全题集的分数**不能直接比较**，引用时必须写明题集。

顺带一个观察：三次采样的差异全部来自少数几道题的翻转（L0 在 6–7 之间、L3 在 21–23 之间），
不是整体水平波动，说明噪声集中在**边缘题**上。
