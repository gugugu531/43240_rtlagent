## 计划提供的三个入口

| 入口 | 正常流程 | 最大模型请求次数 |
| --- | --- | --- |
| `tool_feedback` | 首稿、接口/编译/综合、自身明确错误或受支持输出警告、至多一次修复、复验 | 2 |
| `spec_test_repair` | 首稿、接口/编译、独立公共规格计划、自测、有独立属性依据时至多一次修复、再自测、允许时综合 | 3 |
| `behavior_divergence` | 共用首稿、第二份独立候选、同一规格计划与激励、记录行为分歧、至多一次有依据的修复、复验 | 4 |

上限包含首稿、独立候选、计划和修复的实际模型请求；不自动重试。公开真值表枚举不调用模型，不能记成一次已执行调用。
请求失败也占用已经启动的请求额度；计划不可用不能偷偷再生成一份。每题仍受既有 token 账本、整题时间预算和 Supervisor 硬截止约束。
第二份候选只看公开题面，不看第一份代码。行为分歧只是观察，不是错误证明；两份答案相同也不是正确证明。

## 架构和拟定接口

正式代码主要增加 `agent/workflows/spec_repair.py`，不恢复旧版 `agent/policies/`。
共享编排类拟命名为 `ExperimentalRepair`，避免与队长现有 `EvidenceRepair` 重名。
三个注册类只声明各自的候选数、是否自测和固定调用上限；选择及失败策略仍归 Workflow 所有。

拟定的内部接口：

```python
class ExperimentalRepair(Component):
    def run(self, ctx) -> WorkflowResult: ...
    def _initial(self, ctx): ...
    def _generate(self, ctx, *, parent=None, feedback='', alternative=False): ...
    def _ensure_plan(self, ctx) -> PlanResult: ...
    def _verify(self, ctx, candidate, *, plan): ...
    def _repair_basis(self, ctx, candidate, checks): ...
    def _choose(self, ctx, *, plan, repair_basis) -> SelectionDecision: ...
    def _record_divergence(self, ctx, plan): ...
```

所有动作通过 `ctx.execute()`，模型和工具走 `ctx.llm`、`ctx.tools`；不增加第二套求解入口。
注册表只增加导入，正式默认配置与 `single_generate` 不变；新增三份开发配置显式选择实验入口。
修复提示必须保留公开规格、完整候选及必要的输入历史，不能把截断摘要当成完整时序依据。

### 首稿与共享检查点

计划复用队长方案 A 的首稿消息和提取节点：`rtl_generate(prompt_style='repair', use_skills=False,
temperature=0, top_p=1, max_tokens=8192)` 与 `rtl_extract`。
三个实验入口的首次请求必须一致；第二候选默认 temperature=0.4、top_p=1，明确记录为策略差异。
修复 temperature=0、top_p=1，计划保持第三批的 temperature=0、top_p=1。

这不是官方 `single_generate` 的请求/提取规则，不能声称与官方 baseline 逐字节相同。
选择该起点是为了复用主线已有、严格限定方案 A 消息的 `load_initial()`，不修改官方 baseline 或放松检查点校验。
后续正式配对实验应将这份首稿本身作为“无修复对照”，并与官方 baseline 分列报告。

新入口拟支持现有 `runtime.initial_state`：恢复同一 solver-only（仅求解信息）首稿、扣除已有实际时间和 token 成本，
继续计算总请求数，不读取官方判定目录。直接启动时保存自有 `initial.json`，保存位置在计划生成、第二候选和修复之前。
编译错误也保留初始状态。已有检查点的 `synth_passed` 不能让规格组跳过自测；重放不是零成本实时部署。
实验汇总、官方首稿/最终评分配对、重复采样和统计工具仍是第五批，不混进本批运行依赖。

## 必须落实的安全边界

1. **修复后先复验再替换。** 首份可用答案立即持久保存。新稿先做接口和编译，规格组再做相同计划自测，允许时才综合；
   不能先凭 lint 较好选中新稿，随后超时把没有自测的新稿留作最终答案。
2. **补齐编译修复后的功能阶段。** 首稿不能编译时可以修复；修好后即使修复次数已用完，也必须尝试计划和自测。
   计划缺失、工具失败或时间不够时明确记录功能未验证，不能直接跳过该阶段并宣称通过。
3. **沿用第三批严格保护。** 普通模型期望值失配不能单独触发功能修复或替换可编译旧稿。
   有效公开属性反例才允许功能修复；择优继续使用同计划、相同属性集合、保住旧通过项、严格减少失败项及完整端口/复位探针保护。
   不为了获得更多修复次数放松计划校验或扩大支持范围。
4. **驱动警告不绕过属性保护。** 工具组复用 `driver_repair_improves()` 的完整接口和严格警告减少条件。
   规格组若只有警告、没有能支持第三批严格属性改进的证据，本批保留并报告警告，不另开“警告优先”替换通道。
   有属性修复时也必须复查综合，不能用功能自测掩盖已有工具证据退化。
5. **分歧不作为裁判。** 第二候选的模型期望匹配率、两稿是否一致和模型自述均不决定正确性。
   未知样本、X/Z、TB 编译/展开失败、工具缺失和环境错误不作为 DUT 功能错误。
6. **早停和失败回退。** 满足本组检查且无可修复问题时早停；无可靠计划、仅模型假设失配、环境失败或预算耗尽时保留已有答案并标明停止原因。
   不将 `BudgetExhausted` 一律记成时间耗尽：模型请求上限、token 限额和时间截止应分别记录。
7. **保留队长最新修补。** 证据引用的段落边界和未知观察分类不回退；不修改原有 E1/E2、检索、检查点验证和正式默认行为。

## 验收计划

先用固定假模型和可控工具验证下列流程，再用本地真实 Vivado 运行人工构造的最小电路：

| 验收项 | 必须检查的结果 |
| --- | --- |
| 注册与隔离 | 三个入口能独立构造；默认入口、E1/E2 请求和结果不变；没有 dev 的提交包可运行 |
| 首稿一致与重放 | 三组首次请求/提取一致；同一 initial.json 可恢复；费用/时间不归零；不读官方评分 |
| 调用上限 | 分别不超过 2/3/4 次；失败、计划不可用、真值表零调用均按实记录 |
| 编译修复 | 原稿编译失败、修复成功后必须出现功能阶段；之后才能综合 |
| 计划回退 | 时序依据拒绝、模型错误、截断和 TB 故障不错误修复、不虚报功能通过 |
| 未知观察 | X/Z、部分未知和确定失配并存时沿用最新协议，不把未知算通过 |
| 候选保护 | 模型期望较好但无属性改进不能换稿；丢旧通过项、改端口、丢探针区分度不能换稿 |
| 中断保护 | 新稿 lint 后、自测前或综合中截止，已验证旧稿仍在输出文件中 |
| 可信反例修复 | 公开真值表错误可触发修复，同一完整计划重跑后按严格证据择优 |
| 时序修复 | 同步/异步复位最小电路验证采样顺序与观察前态探针，不使用模型预测末态作依据 |
| 输出警告 | 工具组在原一次修复额度内处理；规格组不能绕过严格属性保护 |
| 双候选分歧 | 完整同激励才可比较；只分歧无独立依据时不修、不投票；后出现的稿不提前覆盖旧稿 |

最后运行完整离线回归、提交包完整性检查、默认入口 smoke 和新入口 smoke；真实工具的条件跳过与单独启用结果分开记录。
不预填测试数和通过数字。失败历史如实保留，不能以这批组件验收宣称题集通过率提升。
