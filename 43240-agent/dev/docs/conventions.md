# 开发规范

## 仓库边界

主办方原始文件只读：根目录 README.md、SCORING.md、REPORT_TEMPLATE.md、.gitignore，以及
 docs/、selftest/、example/。不得修改 43240-agent/baseline.py 和 run_baseline.sh。

43240-agent/ 是参赛方案；dev/ 是开发区，不随方案提交。参考答案、测试台和官方判定信息只能
留在开发区或主办方判定链路，不能进入 Agent、技能、提示或其他提交文件。
方案断网运行，依赖和开源模型权重必须预先准备；具体比赛要求以 SCORING.md 为准。

不得提交 API key、Cookie、令牌、remote.env、cloud.state、selftest/env.sh、模型权重或运行日志。
固定赛事文件名遵循原始要求；新增提交文件的名称使用英文小写字母、数字、下划线或连字符。

## 目录与依赖

| 位置 | 职责 |
| --- | --- |
| agent/core/ | 契约、配置、注册表、运行上下文、运行器与监督 |
| agent/services/ | 模型、进程和 Vivado 等外部服务 |
| agent/nodes/、workflows/、policies/ | 动作、Python 流程与可复用策略，实验变体也放这里 |
| agent/prompts/ | 提示模板、构造与技能选择 |
| agent/recording/ | trace、证据、原子产物与通用运行指标 |
| config/ | 正式入口默认配置 |
| dev/tools/ | 统一实验、开发判定、远端管理、历史分析与打包检查 |
| dev/configs/ | 实验配置、任务与排除清单 |
| dev/tests/ | 组件、流程、监督及打包测试 |
| dev/runs/ | 原始实验产物，只保存在本地 |
| dev/docs/ | 所有团队开发文档 |

Python 定义 Workflow、组件选择和参数，YAML 选择已注册 Workflow、服务、运行条件与实验。
不在 YAML 中重复定义流程图或 bindings。注册只登记实现类，每题构造独立实例。

Workflow 和 Node 只依赖共享契约与公开上下文；正式代码不得导入 dev 或 selftest。
Node 返回结果，下一步由 Workflow 决定。通过 ctx.execute() 执行动作，模型与工具使用上下文
统一接口，自动获得证据、预算和监督；自行脱离受管理进程组的后代不受回收保证。

求解统一通过 run.sh 和 Supervisor；开发实验通过 dev/tools/run.py。官方判定作为可选指标，
结果不回传求解上下文。参考答案链路验证直接用未改动的 selftest/run_selftest.sh --reference，
输出放 dev/runs/。不维护第二套 Agent 求解循环。

## 文档

统一入口为 [readme.md](readme.md)，规范只维护在本文。

| 位置 | 内容 |
| --- | --- |
| design/ | 长期维护的架构、接口、配置和工具用法 |
| notes/ | 设计讨论、进展、决策和失败分析，注明类型、状态、日期和来源 |
| experiments/ | 每次实验的假设、结果、结论及原始记录位置 |

设计写计划，进展另写验证结果；数字注明运行编号，未知留空。当前手册与参考只写已实现行为。历史笔记在索引中归档并注明状态，保留当时结论；不得删除实验、验证、决策及类似记录。旧实验原始数据和历史命令不自动转换成新格式。
历史文件名保留，新笔记使用 YYYY-MM-DD-<主题>.md；新实验使用实际运行编号。

生成内容必须注明生成命令和不要手改；人工假设与结论写在生成块外。迁移脚本可以更新生成块的
路径引用，不改动历史测量值。重新生成结果时只更新对应块，不覆盖人工结论。
归档采用文档状态和统一索引分类，不新增 archive 目录。生成表格、原始实验与资源数据不为归档重写；历史证据与当前指南分别阅读。

正文用中文和日常说法，不自造缩写。专有名词保持原样，含义不明显的术语首次解释。
skill 下 SKILL.md 沿用英文技能格式。代码注释沿用模块已有语言。

方案 README 描述当前结构和行为，代码结构或行为变化时在同一 commit 更新。MODEL.md 与
manifest.json 在模型或提交服务策略变化时同步更新；暂不编写 REPORT.md 的实测结论。
阶段开始前先提交架构、函数接口与验收计划给用户审阅，认可后实施。

## 代码与验证

- Shell 使用 set -eo pipefail，不加 -u，避免破坏 Vivado 环境脚本。
- 工具位置从配置、PATH 或官方环境变量取得，不写死安装路径。临时文件使用本地盘独立目录。
- 新增依赖写入 requirements.txt；正式运行不能下载依赖、模型或扩展。
- 未处理异常和中断保留已选择答案；没有候选才输出空文件。必需产物写入失败不能伪装成功。
- 每次模型与工具调用必须记录 trace；记录实际开始、结束和缺失状态，不伪造调用完成。
- 未知 token、未执行、环境失败与代码未通过分开统计；官方计分继续使用原判定与聚合规则。
- 按改动运行必要组件测试、回归和单题 smoke；正式代码必须能在没有 dev 的目录中运行。
- 用 dev/tools/submission.py 检查和暂存明确文件清单。它不复制 dev、任务或外置模型权重，
  不替代参考答案审核、依赖准备、官方基础镜像构建和目标 GPU 验证。

## Git 与 PR

不直接向 main 提交或推送。在独立分支实施，经 PR（合并请求）审查后合并。
正常从更新后的 main 创建分支；既有分支不为迁移改写已推送历史。有冲突时合并 main 再处理。
正常 PR 使用 Rebase and merge；已通过合并 main 处理冲突时使用 Create a merge commit。

提交信息只写一行英文标题：<类型>(<范围>): <说明>，动词原形开头，不写正文，不加
Co-Authored-By。类型为 feat、fix、refactor、docs、test 或 chore。
一次提交聚焦一个阶段或问题；目录重构不混入策略试验。

提交前检查状态和暂存清单，不包含 runs、凭据或用户已有未提交文件；两个 baseline 与 example
逐字节一致。创建 PR 前检查整个分支差异。是否推送遵循用户当前授权，本轮阶段只本地提交。

云端实例持续计费，用完立即销毁；长时间测试阻止本机休眠。目录迁移只作离线检查，不启动实例。
