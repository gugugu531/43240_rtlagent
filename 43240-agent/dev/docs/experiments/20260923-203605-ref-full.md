## 结论

判定链路正常：155 道 VerilogEval 题和 3 道示例题中，155 道判到 L3，没有环境失败。

有 3 道题的参考实现只判到 L1：`Prob082_lfsr32`、`Prob141_count_clock`、
`Prob156_review2015_fancytimer`。三道的失配数都是 0（199999 个采样点），但测试台打印了
`TIMEOUT`，判定器按 L2 失败处理。原因是测试台本身：激励要跑约 200,000 个时钟周期
（约 2,000,000 ps），而测试台自带的超时块只有 `#1000000`（1,000,000 ps）。单独重新判定
结果相同，与并行负载无关。

`selftest/README.md` 说 155 道参考实现全部通过，那次检查只看了失配数，没有算上测试台
打印的 `TIMEOUT`，而判定器 `veval-judge` 是算上的。

处理：这 3 道题加入 `eval/tasksets/exclude.txt`，默认不跑；`quick` 子集中的
`Prob082_lfsr32` 换成同题型的 `Prob105_rotate100`。排除后 VerilogEval 剩 152 道。
评测题集如果也有这类测试台，任何方案在这些题上都拿不到 L2 以上。
