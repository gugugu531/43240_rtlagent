# 日志查看器

`dev/tools/log_viewer.html` 是一个独立 HTML 文件，不依赖安装包或网络服务。直接用浏览器打开，
点击“选择日志目录”，选择含 `trace.jsonl` 的单题输出目录，或包含多个样本的实验目录。
导入整个实验时，“运行记录”可以切换 Agent 与 baseline 等不同样本。

## 可以查看什么

- 左侧默认用简单流程图展示 Workflow：方框代表执行步骤，箭头表示实际先后，框内展示模型和工具调用。
  循环按实际轮次展开，不推测未执行的分支；也可切换为事件列表。
- 点击 Node 可以查看其输入、输出摘要，以及内部模型调用的请求和回复。
- 点击模型调用，在“请求”查看参数与消息，在“响应”查看正文、思考内容和完整响应。
- 检查显示通过、失败、超时、不可用、跳过等状态，复用检查另有标记；导入了对应日志时可查看全文。
- Workflow 的“响应”包含最终答案；“概览”包含求解、监督和最终选择记录。
- “原始事件”保留事件原有字段；搜索框和状态筛选用于定位问题。
  筛选后隐藏连接箭头，避免把省略中间步骤的结果误当作完整流程。

这里显示的是实际执行记录，不推测未执行的分支。Node 成功表示动作正常返回，并不保证它
执行的检查通过；以具体检查结果为准。只有开始事件的调用显示“未见结束”，不假定仍在运行。
Workflow 的完成状态优先读取 `agent.done`，监督中断另行体现。旧格式没有这些信息时显示未知。

当前记录中 Node 的组件和输入只在开始事件里，结束事件只有耗时和输出摘要，查看器会合并两者显示。
检查日志按 `log_paths` 读取，候选代码读取 `candidates/<id>.v`。旧记录里的 `full_log_path`、
`candidates/<id>/solution.v`、`content.txt` 等文件仍然可以显示。

## 导入范围

完整查看建议选择 `samples/agent/<task>/s0/` 这一层，连同 `records/` 一起导入。
也可以直接选择 `dev/runs/<实验编号>/`。页面忽略源码快照 `source/`，不把它当作运行证据。

单独打开或拖入 `trace.jsonl` 只能看到事件中已有的字段。若配置了外部记录目录，可再次选择
含对应 `run_id` 子目录的记录根目录，补充请求和回复。文件引用不能唯一匹配时不猜测归属。
不支持压缩包；需要先解压。重新选择同一个目录可更新文件，刷新页面会清空已导入内容。

baseline 的原始 trace 没有 Node 结构，按调用事件展示。如果同一输出目录附带本次实验式的
`model_capture/`，也能查看对应请求和回复。查看器不会自行运行模型或工具。

文件通过浏览器 File API（本地文件读取接口）读取，不上传，不保存到浏览器持久存储。
模型回复、工具输出和文件名均作为文本呈现，不执行其中的 HTML 或脚本。详细证据缺失、损坏
或未匹配时，会显示缺失提示或原始文本；不能把“看不到响应”解释为模型没有返回。

## 实现与验证

解析和分组由单文件内的 `TraceParser.parse(text)`、`TraceParser.build(events)` 完成。
按 `execution_id`、`call_id`、`check_id`、`process_id` 合并生命周期，并按执行归属展示。
文件索引按需读取正文，切换节点时丢弃过时的异步渲染结果。

在 `43240-agent/` 下执行不需要第三方依赖的解析回归：

```bash
node dev/tests/test_log_viewer.cjs
```

回归覆盖开始与结束合并、重复调用、嵌套、复用、残缺 JSONL、空日志、中断、旧 baseline、
Workflow 与监督状态的区别、只在开始事件带组件的 Node，以及错误父子关系不会造成死循环。
浏览器验收应包括真实目录导入、样本切换、节点请求与响应、缺失文件提示和窄屏布局。
