## 1. 设计目标

输入纯文本题面，生成 `solution.v`，记录每次模型与工具调用。正式评测不提供参考答案和
参考测试台，方案不读取开发题库中的判定材料；`interface` 可为空，接口信息由题面提供。

能力目标、归一化增益目标与墙钟预算的实测依据：待填写。

## 2. 总体架构

默认入口为 `run.sh` → Supervisor（进程监督）→ Worker → `single_generate`。
默认流程调用一次模型，使用本地未修改 baseline 的提示、采样和提取规则，不加载技能或调用 Vivado。
输出通过恢复检查点和原子替换保存；未能得到答案时输出空文件。停止与错误原因写入 trace。

可选的修复、结构化诊断与规格自测流程见 [README](README.md)。这些流程需要显式选择，
未证明完整题集收益之前不作为已确定的最终提交策略。

HTTP 投题层独立于求解流程：立即返回任务编号，后台串行解题，通过查询接口取得结果。
nonce 用于重复投递去重，时限覆盖排队和执行；HTTP 服务与 Agent 共同管理任务进程清理。

## 3. 模型与推理服务

模型来源、revision（固定版本的 commit 哈希）、许可证、量化方式与目标硬件实测显存：
待在 [MODEL.md](model/MODEL.md) 与 `manifest.json` 同步填写。当前 Qwen3-8B 是示例配置。
权重地址须公开可访问；权重提前准备到本地，正式断网运行时不下载。

当前默认模型请求的 temperature 为 0.0、top_p 为 1.0、单次输出上限为 16384 token。
示例服务上下文为 32768，最终值须与基线完全一致。模型与服务尚未最终选型。

`serve/start.sh` 是常驻服务统一入口；推理服务绑定环回地址，默认按 30 GB 预算计算
显存比例。预算不是实测峰值，显式比例覆盖后须重新核对单卡 32 GB 上限。

## 4. 智能体、技能与基线

默认 `single_generate` 单次生成，不重试。Supervisor 管理硬期限与已选择答案恢复；
未完成的模型调用保留开始事件，不伪造完成记录。客户端停止不等于证明推理后端已取消请求。

可选 Workflow、工具与技能触发方式以 README 和实际运行记录为准。正式提交采用的流程、
技能来源、适用边界与消融实验：待填写。

`baseline.py` 和 `run_baseline.sh` 按本地受保护原文件保留；基线不运行技能、工具或 MCP。
本地 baseline 已原样同步到上游 `f7a8bd4`，包含 `strip_think()` 和 manifest 思考声明加载；
输出上限 16384，单次请求上限 840 秒。方案采用同一思考声明，默认单题预算 900 秒。

## 5. 预算与记录

单题从投题开始计时，包含排队、输入准备、执行与清理。无法求解时返回空答案，
临时请求目录在后台求解结束后清理；详细记录需要配置独立的 `AGENT_RECORD_ROOT`。

trace 记录模型请求、token 用量、候选来源、工具结果与监督状态；未知用量保持未知。
HTTP 层可追加服务超时与异常类别。正式模型调用不得由 mock 结果替代。

| 消融 | 同起点、同预算对照及逐题变化 |

按上游当前规则，归一化增益为：

```text
g = (方案题集得分 − 基线题集得分) / (1 − 基线题集得分)
增益得分 = 40 × min(g / 0.6, 1)，g ≤ 0 时为 0
基线为 1.0 时增益项计满分；基线为 0 时 g 等于方案题集得分。
```

模型之间的历史筛选数字、mock 流程验证和工具替身检查不填作本报告的正式能力结论。

## 8. 复现与封存

以实际官方基础镜像、固定 revision 的本地权重与预先安装依赖构建方案。完整使用说明见 README。

```bash
export MODEL=/models/Qwen3-8B
export MODEL_NAME=Qwen3-8B LLM_MODEL=Qwen3-8B
export LLM_BACKEND=openai LLM_BASE_URL=http://127.0.0.1:8000/v1
./serve/start.sh
./run.sh <input_dir> <output_dir>
./run_baseline.sh <input_dir> <baseline_output_dir>
```

远程投题另启动一个 uvicorn Worker，经 `rc-tunnel` 暴露 7860；三个端点均校验赛事令牌。
