Title:
- Square Root Calculation using Newton-Raphson Method with Fixed-Point Arithmetic

Objective:
- The goal is to design and implement a module capable of calculating the square root of an input number using Newton-Raphson's iterative method.
- The module should accept and produce input and output values in fixed-point format, ensuring high precision and efficient hardware implementation.

Background:
- Newton-Raphson's method is a numerical technique for finding successively better approximations to the roots (or zeroes) of a real-valued function.
- For square root calculation, the method is applied to the function f(y) = y^2 - X, where X is the input number and y is the square root estimate.
- The iterative formula is: y_{n+1} = (y_n + X / y_n) / 2.
- Fixed-point representation is a numerical format used in hardware designs to trade off precision and resource usage by representing numbers with a fixed number of fractional bits. X, sqrt_result, and all internal values are UNSIGNED, since square roots of negative numbers are imaginary and out of scope.

Design Constraints:
- The design should support configurable bit-widths via N (default 16) and a parameterized number of fractional bits M (default 8), plus a configurable iteration budget ITER_MAX (default 10).
- It must handle fixed-point arithmetic correctly, including appropriate scaling and normalization to ensure accurate results.
- Initial Guess: use y0 = X as the starting point for the iteration. This choice needs no extra setup logic and converges within ITER_MAX=10 across the full representable range of X.
- Zero Input: X=0 must be special-cased to directly output sqrt_result=0, bypassing the iteration, otherwise the first division (X/y0) is 0/0.
- The implementation should include a control finite state machine (FSM) to manage the iterative processing steps, convergence checking, and output readiness.
- Clocking assumptions, timing constraints, and reset behavior must be clearly defined and adhered to for proper integration into larger systems.

Performance Expectation:
- A sequential (iterative) implementation reduces area at the cost of latency; ITER_MAX=10 provides comfortable convergence margin for the default N=16, M=8 configuration.

Deliverables:
- A synthesizable HDL module (Verilog/VHDL) implementing the square root calculation using Newton-Raphson's method with fixed-point arithmetic.

Design Name:
- TopModule

Module Name:
- TopModule

Inputs:
- clk: Clock signal (used for sequential implementation).
- rst: Synchronous reset; clears internal registers and returns FSM to IDLE.
- start: Start signal that latches the input X and initiates a new computation.
- X[N-1:0]: The input number for which the square root is to be calculated, UNSIGNED Qn.m fixed-point (N total bits, M fractional bits).

Outputs:
- sqrt_result [N-1:0]: The calculated square root, UNSIGNED Qn.m fixed-point, same format as X.
- ready: Asserted when the computation is complete and sqrt_result is stable. Held until the next rst or start.

Design Signature:
module TopModule #(
    parameter N = 16,   // total bit width (Qn.m format)
    parameter M = 8,    // number of fractional bits
    parameter ITER_MAX = 10    // maximum CALC iterations before forced exit to DONE
)(
    input                  clk,
    input                  rst,
    input                  start,
    input  [N-1:0]         X,
    output reg [N-1:0]     sqrt_result,
    output reg             ready
);

Design Notes:
- Implements Newton-Raphson's iterative method for square root calculation using the formula: y_{n+1} = (y_n + (X / y_n)) / 2, adapted for fixed-point arithmetic.
- The input and output are represented in fixed-point format with M fractional bits (Qn.m notation), where N = integer bits + fractional bits.
- Initial Guess: use y0 = X as the starting point. X is already latched at the start of CALC, so no extra logic is needed.

- Zero Input Special Case: X=0 MUST be special-cased. The recurrence requires computing X / y_n; if y0 is derived from X (e.g. y0=X=0), the first division is 0/0, which is undefined. When X=0, the design must bypass the iteration entirely and output sqrt_result=0 directly.

- A finite state machine (FSM) controls the iterative process and typically has the following states:
  - IDLE: Wait for a 'start' signal to latch the input and initialize the algorithm (X=0 may be detected here or in CALC; either is acceptable as long as NO division by zero ever occurs).
  - CALC: Iteratively refine the square root approximation for up to ITER_MAX iterations using y0=X as the starting point.
  - DONE: Output the final approximation and assert the 'ready' flag.
- The input X is only latched when the start signal is activated, ensuring that a new calculation is initiated only when explicitly requested.
- There is no automatic transition from the DONE state to the IDLE state. The module remains in the DONE state, holding the result and asserting 'ready', until it is reset externally (via rst) to begin a new calculation.
- The module is parameterized via N, M, and ITER_MAX (see Design Signature) to support various bit-widths, fractional lengths, and iteration budgets.
